# 英文布局作用域收敛与中文布局保护

- 分支：`feature/frontend-i18n`；布局基线：`13692eca`。
- 本轮开始时工作区有 12 个未提交文件，已独立保存快照；本轮修改仍留工作区，未暂存、未提交。
- 目标：将首批布局修复限定于英文，保留已验证的中文默认布局。浏览器连接不可用，本轮按用户确认的代码级方案执行，不以未获取的页面作为验证证据。

## 收敛内容

1. **统计卡片与图表**：恢复中文的原有三列比例、各列最小宽度、卡片头间距、说明单行、图例 118px 列宽及 `max-width: 1200px` 单列断点。自动换列、换行和可收缩规则集中在 `.linux-patch-scan-page.is-english` 内。ECharts 中文恢复 `left: 42`、`containLabel: false`，英文继续按标签尺寸布局。
2. **表格宽度语义**：中文恢复 `width` 固定列宽，英文才设置 `min-width`。单纯让中文 `min-width` 等于旧数值，仍会改变 Element Plus 的列宽分配方式，因此不能作为中文恢复。覆盖主机严重程度/重启列及漏洞明细的操作系统、版本、内核、扫描日期；固定操作列仍按语言选择原中文宽度或英文宽度。
3. **Tab、表头和行内动作**：Tab 换行、次要动作最大宽度、表格按词换行、严重程度图标排列和行内按钮 flex 分组全部移入 `.linux-patch-install-page.is-english`。中文表头和动作恢复原有节点排列，仅英文渲染新增容器。
4. **公共侧栏**：英文继续使用展开增宽和多行标题。新增的文本容器及 `.menu-label` 只在英文下出现，中文使用原有标题节点。菜单身份、选中、折叠和路由不变。
5. **公共筛选/操作栏**：已有新规则全部位于 `html[lang='en-US']`，本轮保持该文件不变，并纳入非英文样式基线比对。

`is-english` 只由有效语言是否为 `en-US` 决定，不依靠翻译文本判断布局。没有调整后端内容、主机/补丁标识、查询字段、严重程度值或权限策略。

## 中文保护证据

| 检查 | 结果与边界 |
| --- | --- |
| 非英文 CSS 基线比对 | 将 3 个 Vue scoped SCSS 和公共 `opsmind.scss` 编译后，排除明确的英文规则，再归一注释/格式，与 `13692eca` 比较；选择器、声明、顺序和媒体规则一致。此检查覆盖恢复的 1200px 断点，不只核对几个 CSS 值 |
| 中文模板结构比对 | 对 3 个组件的模板 AST 求值关闭英文分支，移除未启用的英文 class/绑定，归一注释与空白；中文节点、事件绑定及列宽声明与基线一致。比较不包含浏览器像素测量 |
| 真实 Element Plus 列状态 | 检查中文声明为固定 `width`，英文清除固定宽度并设置较大 `min-width`，往返后恢复固定宽度；同时检查实际表格公开 `columns` 状态及实例身份 |
| 状态与请求 | 语言往返保留勾选、漏洞筛选和当前主机身份，不重新读接口或触发业务写请求；原有安装/扫描动作继续传正确主机和 `Critical` 协议值 |
| 既有工作区保护 | 本轮未改的 5 个既有文件与起点逐字节一致：标签 Store、上一轮联合回归说明、两个联合测试，以及公共 `opsmind.scss` |

为了保留中文动作的原始节点排列，英文分组和中文按钮采用明确的条件分支，事件仍调用原处理函数。定向回归同时覆盖行内安装和扫描，避免条件结构改变后误选隐藏列中的占位节点或当前主机。
