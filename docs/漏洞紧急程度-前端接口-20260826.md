# 漏洞紧急程度 · 前端接口

基址 `/api/secops/v2/urgency`，租户从登录态取，不用传。

## 一条规则决定一切

`urgency = 规则表[区域 + 利用程度 + 风险等级]`，**非空 ⟺ 有一条规则命中**。

查不到规则不兜底成"一般"/"未知"，而是**清空成 `null`**。所以：

- 机器没打区域标签、或该区域没配规则 → 它的紧急程度是 `null`
- 机器的区域被**撤销**后重算 → 之前算出的值会被清掉，不会留着陈旧值
- **规则表为空时重算，会把全部紧急程度清光** —— 这是上面那条语义的必然结果，不是 bug

前端凡是展示紧急程度的地方都要能处理 `null`（建议显示 "—" 或"未匹配规则"）。

---

## 1. 统计 · `GET /statistics`

```json
{ "特急": 0, "紧急": 8, "普通": 0, "一般": 2986, "未知": 0 }
```

固定五个键。`null` 的行**不计入任何一个**，所以五项之和通常小于总行数，差额就是没匹配上规则的行。

"未知"这一档现在只可能由历史数据残留，跑过一轮重算后恒为 0（规则只能产出前四档）。

## 2. 列表 · `GET /page`

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `urgency` | 否 | **不传 = 全部**（含 `null` 的行）；传「特急/紧急/普通/一般」按档过滤 |
| `page` | 否 | 默认 1 |
| `size` | 否 | 默认 20，上限 200 |

```json
{ "urgency": null, "page": 1, "size": 20, "total": 8536,
  "rows": [ { "cveId": "CVE-2024-1086", "hostId": "...", "hostKey": "10.216.1.5",
              "osDistro": "kylin", "osVersion": "V10", "osArch": "x86_64",
              "location": "内网环境、孤岛环境", "riskLevel": "高危", "urgency": "紧急",
              "cvss": 7.8, "patchId": "...", "patchStatus": "...", "affectedPkgs": "...",
              "scanDate": "2026-08-25T03:00:00Z" } ] }
```

切"全部"时请把 `urgency` 参数**整个去掉**，不要传空串以外的占位值。

## 3. 重算 · `POST /recompute`

**异步**，立刻返回，不要等。

```json
{ "tenantId": "...", "accepted": true, "message": "重算已在后台开始..." }
```

`accepted=false` 表示已有一轮在跑，本次未受理 —— 按钮置灰即可，不要重试。

## 4. 重算进度 · `GET /recompute/status`

点完 3 之后轮询这个（建议 3 秒一次）。

```json
{ "running": false, "tenantId": "...", "startedAt": "...", "finishedAt": "...",
  "costMs": 61840, "changed": 1934000, "error": null }
```

- `running=true` → 转圈
- `running=false` 且 `error=null` → 提示"已更新 {changed} 条"
- `running=false` 且 `error` 非空 → 把 `error` 显示出来
- `startedAt=null` → 服务重启后还没人点过

## 5. 单机重算 · `POST /recompute-host?hostId=xxx`

同步，返回 `{ "updated": 123 }`。没标签或该区域无规则时，会把这台机器已有的紧急程度清成 `null`，`updated` 是被清空的行数。

## 6. CVE 反查 · `POST /lookup`

```json
{ "cveIds": ["CVE-2024-1086"] }        // 或 { "text": "粘贴一段含 CVE 编号的文字" }
```

返回 `{ "totalInput": 1, "totalRows": 16, "rows": [ 同 /page 的 rows ] }`。

> 这个接口的 `urgency` 是**现算**的，不读库里那一列，所以不受重算时机影响；
> 且此处查不到规则会显示"一般"/"未知"占位。与 `/page` 的值可能不同，属正常。

`POST /lookup/export` 请求体相同，返回 xlsx 文件流。

## 7. 规则 · `GET /rule` · `PUT /rule/{id}` · `POST /rule/import`

- `PUT` 体：`{ "urgency": "紧急", "enabled": 1 }`，两个字段都可选
- `import`：`multipart/form-data`，字段名 `file`，xlsx/xls。四列依次为
  **所处环境 / 利用程度 / 风险等级 / 紧急程度**，首行表头。
  利用程度留空表示通配。校验失败返回 400，`{ "error": "第N行：..." }` 逐行列出。
  导入会**整租户替换**旧规则，成功返回 `{ "imported": 36, "replaced": 0 }`。

---

## 前端流程

1. 导规则（7）→ 2. 给机器打区域标签 → 3. 点重算（3）→ 4. 轮询（4）→ 5. 刷新统计和列表（1、2）

漏了第 1 或第 2 步再点重算：已有紧急程度会被清成 `null`。撤销机器区域标签后也必须再点一次重算（或调 `/recompute-host`），旧值才会消失。
