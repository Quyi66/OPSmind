# 中信国际需求：变更窗口 / 安装审批 / 安装后系统巡检 / 英文语言包 —— 前端接口文档

> 后端分支：boc-3.10.9　　日期：2026-11-12
> 网关前缀：前端经 console 访问时，所有路径前加 `/sjxy-console/secops`，例如 `/sjxy-console/secops/api/secops/v2/patch/change-control/config`。
> 认证方式与现有补丁接口相同。

## 0. 通用约定

### 0.1 时间参数

请求里的时间字段（`planStartTime`、`planEndTime`、`scheduledTime`）支持两种格式：

- 字符串 `"yyyy-MM-dd HH:mm:ss"`（也支持 `"yyyy-MM-dd HH:mm"`），按服务器时区（Asia/Shanghai）解析；
- 毫秒时间戳，例如 `1794470400000`。**建议优先使用时间戳。**

### 0.2 错误返回

业务校验失败时返回 HTTP 400，body 为 `{ "error": "<提示文案>" }`。提示文案已经按当前语言给出，前端直接展示即可。

需要“非变更窗口复核”时同样返回 400，但会多带 `code` 等字段，详见 1.4。

### 0.3 语言

后端按以下顺序确定语言：

1. 请求头 `Language`；
2. 请求参数 `language` 或 `lang`；
3. Cookie `NG_TRANSLATE_LANG_KEY`；
4. 系统参数 `sjxy.language`；
5. 以上都没有时用 `zh-CN`。

取值：`zh-CN` / `en` / `zh-TW`（`en-US`、`en_US` 也按英文处理）。**不读 `Accept-Language`。**

英文界面请在所有 secops 请求上带 `Language: en` 请求头（或保证 Cookie `NG_TRANSLATE_LANG_KEY=en`）。这样错误提示、复核短语、重启说明、审计步骤名称等都会返回英文。

## 1. 需求一：变更窗口

### 1.1 概念

| 名称 | 说明 |
|---|---|
| 变更窗口 | 允许实施变更的时间段，可配置多个：按星期循环（WEEKLY），或指定日期范围（DATE_RANGE）。 |
| 工作时间 | 默认周一至周五 09:00-18:00，可配置。 |
| 申请的实施时间段 | 用户提交申请时选择的 `planStartTime` ~ `planEndTime`。 |

判定规则如下（整个实施时间段每 5 分钟取一个点，有任意一个点落在窗口外就算“不在窗口”）：

| 结果 `result` | 含义 | 决策 `decision` |
|---|---|---|
| `DISABLED` | 未启用变更窗口 | `PASS`，直接提交 |
| `IN_WINDOW` | 整段都在变更窗口内 | `PASS`，直接提交 |
| `OUT_WINDOW_WORK_TIME` | 不在窗口，且落在工作时间 | `CONFIRM`，**弹出复核框，要求输入“确认非变更窗口实施”** |
| `OUT_WINDOW_OFF_TIME` | 不在窗口，也不在工作时间 | 按配置 `offHoursPolicy` 决定：`ALLOW` 对应 PASS，`CONFIRM` 对应 CONFIRM（默认），`REJECT` 对应 REJECT（不允许提交） |

复核短语：中文为 `确认非变更窗口实施`，英文为 `CONFIRM NON-WINDOW IMPLEMENTATION`（忽略大小写）。两种后端都认。前端展示时用接口返回的 `confirmText`（会随语言变化），不要写死。

### 1.2 查询变更管控配置

`GET /api/secops/v2/patch/change-control/config`

响应示例：

```json
{
  "windowEnabled": true,
  "timezone": "Asia/Shanghai",
  "windows": [
    { "type": "WEEKLY", "days": [6, 7], "start": "00:00", "end": "24:00" },
    { "type": "WEEKLY", "days": [1, 2, 3, 4, 5], "start": "22:00", "end": "06:00" },
    { "type": "DATE_RANGE", "startTime": "2026-12-01 20:00", "endTime": "2026-12-02 06:00" }
  ],
  "workHours": { "days": [1, 2, 3, 4, 5], "start": "09:00", "end": "18:00" },
  "offHoursPolicy": "CONFIRM",
  "approvalRequired": true,
  "confirmText": "确认非变更窗口实施",
  "updatedBy": "admin",
  "updatedTime": "2026-11-12 10:00:00"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `windowEnabled` | boolean | 是否启用变更窗口。**默认 false**（未配置时不做窗口约束）。 |
| `timezone` | string | 判定用的时区，默认 `Asia/Shanghai`。 |
| `windows` | array | 变更窗口列表，写法见下方说明。 |
| `workHours` | object | 工作时间，写法与 WEEKLY 窗口相同（不需要 `type`）。 |
| `offHoursPolicy` | string | 不在窗口且不在工作时间时的处理：`ALLOW` / `CONFIRM` / `REJECT`，默认 `CONFIRM`。 |
| `approvalRequired` | boolean | 普通用户提交的补丁任务是否需要管理员审批（需求二），**默认 true**。 |
| `confirmText` | string | 当前语言下的复核短语。 |

窗口写法：

- `WEEKLY`：`days` 为星期 1-7（1=周一，7=周日）；`start`/`end` 为 `HH:mm`。
  - `end` 早于 `start` 表示跨零点（例如 22:00-06:00，指从 days 中那天的 22:00 到次日 06:00）；
  - `end` 等于 `start` 表示全天；
  - `end` 可以写 `24:00`。
- `DATE_RANGE`：`startTime`/`endTime` 为 `yyyy-MM-dd HH:mm`（或带秒）。
- 时间区间都是左闭右开：结束时刻本身不在窗口内，但实施时间段的结束时刻恰好等于窗口结束时刻时，算在窗口内。

### 1.3 保存变更管控配置（仅管理员）

`PUT /api/secops/v2/patch/change-control/config`

body 字段同 1.2（不用传 `confirmText`、`updatedBy`、`updatedTime`），**只更新传了的字段**。返回保存后的配置（同 1.2）。

- 非管理员调用返回 403，body 为 `{ "error": "只有管理员可以修改变更管控配置" }`。
- 写法错误返回 400，例如窗口格式不对、时区无效、启用窗口但 `windows` 为空。

### 1.4 预判实施时间（提交前调用，决定是否弹复核框）

`POST /api/secops/v2/patch/change-control/check`

请求：

```json
{ "planStartTime": "2026-11-13 10:00:00", "planEndTime": "2026-11-13 12:00:00" }
```

两个字段都可以不传，不传按当前时间判定。

响应：

```json
{
  "windowEnabled": true,
  "result": "OUT_WINDOW_WORK_TIME",
  "decision": "CONFIRM",
  "needConfirm": true,
  "confirmText": "确认非变更窗口实施",
  "inWindow": false,
  "workTime": true,
  "planStartTime": "2026-11-13 10:00",
  "planEndTime": "2026-11-13 12:00",
  "nextWindowStart": "2026-11-13 22:00",
  "timezone": "Asia/Shanghai",
  "message": "申请的实施时间不在变更窗口内且处于工作时间，需要复核：请输入“确认非变更窗口实施”后再提交（下一个变更窗口开始于 2026-11-13 22:00）"
}
```

前端处理方式：

- `decision=PASS`：直接提交；
- `decision=CONFIRM`：弹出复核框，展示 `message`，让用户输入 `confirmText`。输入完全一致才允许点“提交”，提交时把输入值放进 `nonWindowConfirmText`；
- `decision=REJECT`：提示 `message`，不允许提交，可以引导用户改到 `nextWindowStart` 之后。

> 这个接口只做预判。**真正的校验在创建接口里**，没调预判直接提交也会被拦下（见 1.5）。

### 1.5 创建任务接口新增字段（所有补丁任务创建接口通用）

适用接口：

- `POST /api/secops/v2/patch/task/create`（补丁安装，Linux / Windows）
- `POST /api/secops/v2/patch/task/create-rollback`（回滚，Linux / Windows）
- `POST /api/secops/v2/patch/task/create-pkg-update`（软件包更新）
- `POST /api/secops/v2/patch/task/create-vuln-fix`（漏洞修复）
- `POST /api/secops/v2/patch/task/create-and-run`（一键包集定时安装；这个接口的实施开始时间就是 `scheduledTime`，不用再传 `planStartTime`）

新增 body 字段（都可选，原有字段不变）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `planStartTime` | string / number | 申请的实施开始时间。不传按提交时刻判定窗口，也不限制执行开始时间。 |
| `planEndTime` | string / number | 申请的实施结束时间。超过这个时间后不能再执行；到期还没审批的任务会自动失效。 |
| `applyReason` | string | 申请说明，展示给审批人。 |
| `nonWindowConfirmText` | string | 复核短语。只有需要复核时才传。 |

需要复核却没带短语（或短语不对）时，返回 400：

```json
{
  "error": "申请的实施时间不在变更窗口内且处于工作时间，需要复核：请输入“确认非变更窗口实施”后再提交（下一个变更窗口开始于 2026-11-13 22:00）",
  "code": "NON_WINDOW_CONFIRM_REQUIRED",
  "confirmText": "确认非变更窗口实施",
  "windowCheck": { "...": "结构同 1.4 的响应" }
}
```

**前端只要见到 `code == "NON_WINDOW_CONFIRM_REQUIRED"`，就弹出复核框，用户输入后带上 `nonWindowConfirmText` 原样重新提交。** 其他 400 直接提示 `error`。

创建成功后，返回的任务对象会多出以下字段，可在详情页和审批页展示：

| 字段 | 说明 |
|---|---|
| `planStartTime` / `planEndTime` | 申请的实施时间段 |
| `applyReason` | 申请说明 |
| `windowCheckResult` | 提交时的窗口判定：`DISABLED` / `IN_WINDOW` / `OUT_WINDOW_WORK_TIME` / `OUT_WINDOW_OFF_TIME` |
| `nonWindowConfirmed` | 是否做过非窗口复核（boolean） |
| `nonWindowConfirmedBy` / `nonWindowConfirmedTime` | 复核人、复核时间 |

建议在审批列表里，对 `nonWindowConfirmed=true` 的申请加一个醒目标识，例如“非窗口实施”。

### 1.6 执行步骤也受窗口约束

以下执行接口新增**可选** body `{ "nonWindowConfirmText": "..." }`，原来不传 body 的调用方式仍然有效：

- `POST /api/secops/v2/patch/task/{id}/install/execute`
- `POST /api/secops/v2/patch/task/{id}/rollback/execute`
- `POST /api/secops/v2/patch/task/{id}/restart/execute`（只在真正下发重启时检查）

规则：

1. 当前时间早于 `planStartTime` 时，返回 400，提示“未到申请的实施时间”；
2. 当前时间晚于 `planEndTime` 时，返回 400，提示“申请的实施时间已结束，请重新提交申请”；
3. 提交时已经复核过（`nonWindowConfirmed=true`）的任务直接放行；
4. 否则按“当前时刻”判定窗口：需要复核时返回 400 + `code=NON_WINDOW_CONFIRM_REQUIRED`，交互与 1.5 相同，带上短语重新调用同一个执行接口即可。

预检查、校验、跳过等步骤不受窗口约束。

> 注意：预检查通过后后端会“自动接续安装”。如果此时不在窗口内，自动安装会被拦下，任务停在 `PRE_CHECK_DONE`，`errorMessage` 里写有原因。前端在这个状态下照常显示“执行安装”按钮即可，用户点击后走上面第 4 步的复核流程。

## 2. 需求二：普通用户安装需要管理员审批

### 2.1 行为

- 普通用户（非 `admin`）通过上述任一创建接口提交的任务，状态为 **`PENDING_APPROVAL`（待审批）**，不能执行任何步骤。
- 管理员自己创建的任务直接为 `CREATED`，不需要审批。
- 可在配置里通过 `approvalRequired=false` 关闭审批（见 1.3）。

状态流转：

```
普通用户提交 ──> PENDING_APPROVAL ──审批通过──> CREATED ──> 正常的预检查 / 安装流程
                        │
                        ├──驳回──> REJECTED
                        └──到计划执行时间（定时任务）或 planEndTime 仍未审批──> EXPIRED（系统自动处理）
```

待审批状态下调用执行类接口会返回 400，提示“任务尚未审批通过，不能执行”。

### 2.2 待审批列表

`GET /api/secops/v2/patch/task/list?status=PENDING_APPROVAL&page=0&size=20`（接口已存在）

列表项就是任务对象，可展示 `createdBy`、`taskType`、`hostIds`、`planStartTime`、`planEndTime`、`applyReason`、`nonWindowConfirmed`、`windowCheckResult`。

### 2.3 审批（仅管理员）

`POST /api/secops/v2/patch/task/{id}/approval`

```json
{
  "approved": true,
  "comment": "同意，今晚窗口实施",
  "inspectionHostIds": ["192.168.1.144", "ff8080817..."]
}
```

| 字段 | 说明 |
|---|---|
| `approved` | true 表示通过，false 表示驳回 |
| `comment` | 审批意见，可选 |
| `inspectionHostIds` | 可选。**新增字段**：安装完成后系统巡检的主机（资产 ID 或 IP 都可以）。预设后，巡检页默认勾选这些主机（需求三）。 |

返回更新后的任务对象。任务上与审批相关的字段为 `approvedBy`、`approvedTime`、`approvalComment`。

失败情况（都返回 400）：

- 非管理员调用；
- 任务不在待审批状态；
- 计划执行时间或 `planEndTime` 已过：此时任务会被直接置为 `EXPIRED`，提示让申请人重新提交。

### 2.4 申请人视角

审批通过后，任务变为 `CREATED`，申请人在“补丁安装”向导里继续执行（预检查、安装、重启、校验、巡检）。定时任务（create-and-run）到点后由系统自动执行。

## 3. 需求三：补丁安装流程最后一步“系统巡检”

只支持 Linux 任务。Windows 任务会返回 `inspectable=false`，并给出原因。

### 3.1 巡检页数据

`GET /api/secops/v2/patch/task/{id}/inspection`

```json
{
  "taskId": "8a8a...",
  "taskType": "install",
  "taskStatus": "COMPLETED",
  "inspectable": true,
  "reason": null,
  "presetByApprover": true,
  "defaultHosts": [ { "hostId": "ff80...01", "hostIp": "192.168.1.144" } ],
  "taskHosts":    [ { "hostId": "ff80...01", "hostIp": "192.168.1.144" }, { "hostId": "ff80...02", "hostIp": "192.168.1.145" } ],
  "inspectionRunId": "run-xxxx",
  "inspectionStatus": "COMPLETED",
  "inspectionBy": "zhangsan",
  "inspectionTime": "2026-11-12 22:30:00",
  "lastRun": {
    "runId": "run-xxxx",
    "status": "COMPLETED",
    "hostTotal": 1,
    "hostChecked": 1,
    "message": null,
    "startedAt": "2026-11-12 22:30:00",
    "finishedAt": "2026-11-12 22:31:10",
    "counts": { "HEALTHY": 1 },
    "hosts": [
      {
        "hostId": "ff80...01",
        "hostIp": "192.168.1.144",
        "hostname": "app01",
        "os": "Kylin Linux Advanced Server V10",
        "score": 95,
        "status": "HEALTHY",
        "checkTime": "2026-11-12 22:31:10",
        "risks": ["系统负载 2.1（2 核）：1 分钟负载超过 CPU 核数，进程排队，CPU 或 I/O 存在瓶颈"],
        "items": [
          { "code": "cpu", "name": "CPU使用率", "value": "12%", "level": "NORMAL" },
          { "code": "load", "name": "系统负载", "value": "2.1（2 核）", "level": "WARNING" }
        ]
      }
    ]
  }
}
```

| 字段 | 说明 |
|---|---|
| `inspectable` / `reason` | 当前能否发起巡检；不能时 `reason` 为原因，例如“安装/回滚完成后才能发起”“巡检进行中”“不支持 Windows”。 |
| `defaultHosts` | 默认勾选的主机：审批时预设过就用预设的（此时 `presetByApprover=true`），否则用任务主机。 |
| `taskHosts` | 本任务的主机，作为可选范围。管理员还可以手工补充租户内其他 Linux 主机（填 IP）。 |
| `inspectionStatus` | 最近一次巡检的状态：`RUNNING` / `COMPLETED` / `FAILED`；从未巡检时为 null。超过 6 小时没回传结果按 `FAILED` 处理。 |
| `lastRun.counts` | 按主机状态计数。 |
| `lastRun.hosts[].status` | `HEALTHY` / `WARNING` / `CRITICAL` / `UNREACHABLE`。 |
| `lastRun.hosts[].items[]` | 检查项。`code` 是稳定编码，英文界面用语言包 `secops.health.item.<code>` 翻译；`level` 为 `NORMAL` / `WARNING` / `CRITICAL`。 |
| `lastRun.hosts[].risks[]` | 风险说明文本（目前只有中文）。 |

可发起巡检的任务状态：`INSTALL_DONE`、`INSTALL_FAILED`、`ROLLBACK_DONE`、`ROLLBACK_FAILED`、`RESTART_PENDING`、`RESTART_DONE`、`VALIDATE_FAILED`、`COMPLETED`。可以重复发起，但上一次没结束时不能再发起。

**巡检进行中（`inspectionStatus=RUNNING`）时，请每 5~10 秒轮询本接口**，一般 1~3 分钟出结果。

### 3.2 发起巡检

`POST /api/secops/v2/patch/task/{id}/inspection/execute`

```json
{ "hostIds": ["192.168.1.144", "ff80...02"] }
```

- `hostIds` 可选，资产 ID 或 IP 都可以；不传就用 `defaultHosts`；
- 管理员可选租户内任意 Linux 主机，普通用户只能选本任务内的主机；
- 返回结构同 3.1（此时 `inspectionStatus=RUNNING`）；
- 失败返回 400 `{ error }`，例如主机不存在、选了 Windows 主机、选了任务外的主机、上一次还在跑。

### 3.3 流程审计里的巡检步骤

`GET /api/secops/v2/patch/task/{id}/audit/detail` 的 `steps` 中，发起过巡检的任务会多出一个 `step="INSPECT"`（系统巡检）的步骤，状态为 SUCCESS / FAILED / RUNNING。`steps[].label` 已随语言切换。

### 3.4 前端页面建议

在向导最后一步（校验之后，或者任务进入 COMPLETED 之后）增加“系统巡检”页：

1. 进入页面时调用 3.1。`inspectable=false` 时置灰按钮，并显示 `reason`；
2. 主机选择框的可选项为 `taskHosts`，默认勾选 `defaultHosts`；管理员额外允许输入 IP；
3. 点击“开始巡检”调用 3.2，然后轮询 3.1，直到 `inspectionStatus` 不是 RUNNING；
4. 结果按 `lastRun.hosts` 展示：每台主机显示状态、得分、风险列表，展开后显示检查项明细。

## 4. 需求四：英文语言包

### 4.1 支持的语言

`GET /api/secops/v2/i18n/languages`

```json
[ { "code": "zh-CN", "name": "简体中文" }, { "code": "en", "name": "English" }, { "code": "zh-TW", "name": "繁體中文" } ]
```

### 4.2 取后端语言包

`GET /api/secops/v2/i18n/messages?lang=en&prefix=`

| 参数 | 说明 |
|---|---|
| `lang` | `zh-CN` / `en` / `zh-TW`。不传时按 0.3 的规则判断请求语言。 |
| `prefix` | 可选，按 key 前缀过滤，例如 `app_secops.log.`、`secops.status.`。 |

响应：

```json
{
  "lang": "en",
  "messages": {
    "app_secops.log.install_success": "Patch installed successfully",
    "app_secops.log.machine_count": "Completed, {machine_count} machines in total",
    "secops.status.PENDING_APPROVAL": "Pending approval",
    "secops.health.item.cpu": "CPU usage"
  }
}
```

语言包里与前端相关的分组：

| key 前缀 | 用途 |
|---|---|
| `app_secops.log.*`、`secops.host.reboot_*` | 审计日志 `msg_id` 的翻译。占位符 `{xxx}` 对应 msg_id 载荷里的同名字段，例如 `{machine_count}`、`{server}`。 |
| `secops.status.*` | 补丁任务状态名称（包括新增的 PENDING_APPROVAL / REJECTED / EXPIRED）。 |
| `secops.task_type.*`、`secops.step.*` | 任务类型和流程步骤名称。 |
| `secops.window_result.*`、`secops.window_decision.*` | 变更窗口判定结果和决策的名称。 |
| `secops.health.status.*`、`secops.health.level.*`、`secops.health.item.*` | 巡检的主机状态、检查项等级、检查项名称。 |
| 其他（`secops.cw.*`、`secops.task.*` 等） | 后端提示文案。后端已经按请求语言直接返回，前端一般不用自己翻译；其中 `{0}`、`{1}` 为位置占位符。 |

前端自己的界面文案（按钮、表头等）仍然由前端语言包负责。本次新增的页面请补齐英文：变更窗口配置页、复核弹框、审批页、巡检页。

### 4.3 随语言变化的输入短语

| 场景 | 中文 | 英文 |
|---|---|---|
| 非变更窗口复核（`nonWindowConfirmText`） | `确认非变更窗口实施` | `CONFIRM NON-WINDOW IMPLEMENTATION` |
| 确认重启（`/restart/confirm` 的 `confirmText`） | `确认重启` | `CONFIRM RESTART` |

后端两种语言都认（英文忽略大小写）。界面提示请用接口返回的 `confirmText`，确认重启的英文提示文案为 `secops.restart.confirm_text_required`。

### 4.4 后端提示语全面多语言化（影响范围与前端注意事项）

除补丁模块外，以下模块里**返回给前端的提示语**（错误提示、接口 message、展示标签、导出 Excel 的表头/sheet 名/固定文案等）也都已按请求语言输出：资产（CMDB）、公共模块、工作流、基线/审计、工作台。中文界面下文案与原来逐字一致。

**前端必须做**：所有后端请求都带上请求头 `Language: <zh-CN|en|zh-TW>`（或保证 Cookie `NG_TRANSLATE_LANG_KEY` 正确），不只是 secops 接口。

**英文界面下取值会变化的字段**（原来是中文，现在随语言变化）。如果前端按这些字段的中文值做判断或着色，需要改为按右侧的稳定字段判断：

| 接口 / 位置 | 随语言变化的字段 | 改为按此判断 |
|---|---|---|
| 主机漏洞列表 | `reboot_status`、`is_kernel`、`patch_status` | 新增 `reboot_status_code`（system / service / none）；`is_kernel` 原始值；补丁状态码 |
| 漏洞详情 / 受影响主机 | `severityLabel`、`patchStatus`、`needRebootLabel` | `severity`（原始值，仍为中文或英文枚举）、状态码、`needReboot`（布尔） |
| Windows CVE / KB / 中间件 CVE 列表 | `severityLabel` | `severity` / `msrcSeverity` 原始值 |
| 单机补丁列表 `/patch-of-one-machine` | `repoCheck.label` | `repoCheck.status`（INSTALLABLE / NOT_INSTALLABLE / NO_REPO） |
| 系统巡检结果 | `items[].name`、`risks[]` | `items[].code`、`items[].level` |
| 资产导入错误 | 错误 Map 的键（“导入excel内容错误”“资产类型配置错误”） | 只做展示，不要按键名判断 |
| 基线结构图 | 分组名“下线”“其它” | 只做展示 |

**刻意保持中文、不随语言变化的**（它们是数据或匹配值）：

- 审计记录的动作名 `action`（如“补丁安装”“主机重启”“导入资产”“命令审核”）：库里存中文，看板按它筛选和聚合。英文界面请用语言包反查翻译：在 zh-CN 语言包里找值等于该中文的 `secops.audit_action.*` / `platform.audit_action.*` key，再取当前语言的同名 key。
- 统计接口里按严重程度、紧急度分组的 Map 键（如 `bySeverity` 的“严重/重要/中等/低危/未知”、紧急度“特急/紧急/普通/一般/待定”），以及紧急度、风险等级的原始值。显示时可用语言包 `secops.severity.*` / `secops.urgency.*` 翻译。
- SQL 直接产出的少量标签：看板 SQL 里的“系统重启/服务重启/无需重启”，以及已安装包列表里可用版本为空时显示的“无”。
- Excel 导入模板的列名（改了会导致中文模板导入失败），以及“CVE 排查结果反馈模板”这类固定的中文客户表单。
- 资产、自动化等接口里用注解写的参数校验提示（如“密码不能为空”），注解里只能写常量，暂时仍为中文。

**落库文案的语言**：任务失败原因、操作日志备注、审计 `msg_info`、巡检风险说明、仓库采集失败原因等会写入数据库，语言取**写入时**的语言。定时任务、回调线程没有用户请求，按系统参数 `sjxy.language` 输出；切换界面语言后，历史记录不会跟着变。

**其他变化**：

- 统一异常处理（缺少参数 / 服务器内部错误）原来固定返回英文，现在中文界面返回中文。
- 主机重启的复核短语也同时接受 `确认重启` 和 `CONFIRM RESTART`。
- 语言包接口 `GET /api/secops/v2/i18n/messages` 同时返回 secops 与平台模块（`platform.*`）的文案。

**未改造的独立应用**：console（登录、网关、用户与部门管理、License、限流提示）和 executor（执行机回传失败说明）是单独部署的应用，本次只做了评估、没有修改。如需支持英文，需要单独排期，建议改为返回错误码，由前端翻译。
