## 1. 结论

**当前清理方向基本合理，但不能验收为清理完成，也不能据此直接执行原优化计划。** 本次独立确认三项需要整改的问题：软件日志清理未覆盖实际消费者、执行参数翻译存在加载竞态、定时任务简化后缺少可靠的对象识别手段。前三项均有当前代码依据，其中软件日志与同名任务已在本地真实页面复现，参数翻译通过隔离测试复现。

没有证据支持推翻全部修改。展示别名与接口原值分离、内置资源双重身份匹配、运行 ID 不冒充工具 ID、退出旧应用入口但保留关联契约、真实零值与未知值分离，这些方向应保留。不能把“仍有遗留”解释为应全局替换旧字符串。

本轮仅增加本审查报告，未修改业务代码和原七份文档；用于确认翻译竞态的临时测试已移除。未提交、推送或执行真实业务任务。

## 2. 独立理解的需求及证据边界

需求是让 KoreOPS 的用户侧品牌、术语和资源展示脱离旧产品，同时保留可用的业务能力与兼容关系。它不要求删除后台应用模型，也不要求为了看起来不同而重做全局导航、主题或业务流程。

本次按以下边界判断代码：

- 保留现有顶部导航、侧栏、标签页、首页结构和主题；保留用户明确要求的在线状态、连通巡检及“受影响机器”。
- 退出“所属应用”和三个旧应用设置入口属于已确认范围；`appletCode/appCode` 等接口原值仍需保留。

## 3. 已确认问题

### A01 · P2：软件日志仍使用独立的旧格式化逻辑，最新清理没有覆盖该页面

审查时位置：`software/views/LogReportPage.vue:294`，对照当时的 `patches/utils/operationLogMessages.js`。后续解析器在 `9c888e8b` 移至 [src/utils/operationLogMessages.js](../src/utils/operationLogMessages.js)，当前软件消费者见 [LogReportPage.vue](../src/modules/software/views/LogReportPage.vue)。以下原因仍描述审查时版本。关联提交：`634b325b` 的软件日志修改与 `5f211a1c` 的补丁日志修复。

**复现：** 打开 `https://localhost:5573/KoreOPS/#/yum-repo/logs`，今天的六条记录中，Windows 扫描显示 `win_scan_success`，回滚失败显示 `exec_rollback_task_fail`，导入补丁库显示 `patch_is_update`。该观察发生在已访问并加载补丁日志中文内容之后，不能仅归因于首次字典尚未加载。

**原因：** 此页仍有独立 `formatMessage`，只特判短键 `patch_is_update`，没有使用最新针对完整消息键的映射；包含 `#{` 的文本又会提前进入旧翻译分支。源码注释声称后台使用短键，但最终显示的键尾不足以证明这个前提。最新修复只覆盖补丁日志页和弹窗，软件消费者未同步。

**影响：** 同类操作经不同入口查看，结果可读性不一致；失败记录的摘要仍是内部键尾。属于当前清理遗漏，不是后端任务执行失败的新原因。

**建议：** 先取得该页真实原消息，按完整键确认覆盖；在合适的公共层共享消息解析与翻译规则，避免软件模块长期保留另一套分叉实现。保持 JSON 优先解析、零值、原始 `msg_info`、审计文本，并处理字典就绪。不要继续根据页面键尾补猜测映射。

**验收：** 对上述实际四类记录逐条比较两个入口的结果；同时覆盖 JSON、翻译表达式、普通原文、未知键和慢加载。请求及原消息不变。

### A02 · P2：执行参数标签只翻译一次，字典晚到后不会更新

位置：[ExecuteJobDialog.vue](../src/modules/automation/components/job/JobListView/ExecuteJobDialog.vue#L98)，尤其第 121–122 行。关联提交：`e0e844a1`。

`fetchJobDetail` 取得详情后立即 `initializeForm`，将 `translateText(item.label/description)` 的当时结果存入 `formSchema`。共享翻译缓存异步加载，但不是响应式依赖；这里也没有等待 `initTranslations`。首次打开且详情先于字典返回时，参数标签会固定为键尾，字典随后加载成功也不会纠正。

**独立复现：** 使用真实组件、真实 i18n 模块及真实 `jao.json`，仅模拟详情响应并延迟字典 fetch。模拟参数标签与说明为 `#{jao.title}`。释放字典后，`translateText` 已返回“一键作业”，但 `formSchema[0].label` 仍为 `title`，断言失败。此参数是用于隔离时序的测试输入，不声称某个线上工具恰好使用该标签；没有调用执行接口。

**为什么现有测试没发现：** 参数测试采用同步翻译 mock，验证了翻译调用与原参数保留，未覆盖异步资源到达顺序。

**建议：** 表单初始化前等待详情和翻译同时就绪，或让展示字段随翻译就绪重新派生。若调整异步初始化，需同时确保关闭弹窗或切换工具后的旧响应不会覆盖当前表单。保持参数名、默认值、提交值不变。

**验收：** 详情先到、字典先到、关闭/换工具三类场景；检查标签、说明正确且原参数未改。该项属于已新增翻译行为的可靠性修复，不是恢复 D1。

### A03 · P2：定时任务隐藏标识并缩窄搜索后，同名对象缺少操作前辨认手段

位置：[WbCronDrawer.vue](../src/modules/automation/components/workbench/WbCronDrawer.vue#L43)、其 `filteredJobs`，以及 [useCronJobActions.js](../src/modules/automation/components/job/composables/useCronJobActions.js#L158)。同时涉及 `CronJobTable.vue` 移除 ID 列。关联提交：`89cb9e42`、`0a4236d5`。

**真实页面证据：** 本地有两条“PMS回收过期密码”，均停用，Cron 均为 `0 0/5 * * * ?`。完整列表显示它们分别为 REST 接口与巡检任务；工作台抽屉只显示名称、状态和 Cron，两张卡片提供相同的执行、启用、编辑、复制、删除按钮。

**归因边界：** 抽屉同名展示不清晰并非全部由本轮引入；但本轮还移除了按 ID、类型、作者等字段搜索的能力，将空名称的 ID 回退改为统一“未命名定时任务”，并在列表和确认中降低了身份信息。因此不能认定这轮简化已正确完成，也不能把 ID 一概归为旧系统痕迹。

**建议：** 保留简洁主标题，在重名/缺名时提供稳定短标识，并显示任务类型或关联对象；执行、启停、删除确认需要能明确识别同一对象。至少恢复 ID 检索，不必恢复“所属应用”展示，也不必在所有行铺满技术列。

**验收：** 两条真实重名任务、两个无名称任务；列表、抽屉、确认中的身份一致；可按唯一标识定位。无需执行真实任务即可检查这些条件。

## 4. 其他重要判断

### 4.1 日志保留原值不等于摘要语义完整

当前测试 `operationLogMessages.test.js` 明确构造 `scan_count: 1` 与 `scan_failed_count: 99`，仍期待“补丁扫描执行成功……”且摘要不包含失败数量；测试仅另外断言原字段没有被修改。本地也读到了相同结构的“扫描机器数量为1”成功摘要，而目标列显示多个目标。

这是结果表达的潜在误导，不能用“未改原参数”直接证明摘要正确。不过本轮没有独立取得该条在线日志完整原响应，也没有后端字段定义，不能把测试里的 99 直接当成本轮读出的在线失败数量，更不能据此改任务最终状态。建议后续核实 `scan_count/scan_failed_count` 的口径；对有明确失败信息的记录展示限定性结论和失败数量，原始详情继续保留。此项属于语义待核实，不列为已证实的新执行逻辑回归。

### 4.2 79 项映射原则合理，但数量不能代表清理覆盖率

`resourcePresentation.js` 以工具 ID 和已知原名称共同匹配；未知或重命名对象保留，运行记录需有明确 `job_id/jobId`，这些保护应保留。本地已验证部分别名和搜索生效。

230 的 167 条目录与本地 131 条工具不同，不能用 79/167 作为本地完成率。剩余 53 条是旧目录取样口径下的待核实资源，不等于本地恰好还有 53 条待改。

“存在固定前端调用”可作为内置身份的重要证据，但不应成为唯一合法证据。没有固定调用的系统工具也可能由平台登记、任务配置或管理员维护。后续应增加可接受的来源证据及归属确认；证据不足继续保留，不按前缀批量删除。两条巡检名单相关资源还需要先确认实际语义。

### 4.3 已合理处理的部分

- 所属应用从展示退出，但原编辑、执行和关联字段没有被显示别名替换；设置旧路由保留重定向，并处理标签缓存。
- 工具标题身份沿历史、结果、选择器等链路传递；原始名称与技术标识仍可用于请求和排查。
- `SKIPPING` 改为“已跳过”是结果状态展示，不等于重新定义白名单/黑名单的行为；路径缩为文件名展示时保留原路径。
- 漏洞与资产展示区分 0、缺失及无效名称，比默认补成高分/零数量更准确；工作台分页、请求过期保护等局部改进有实际价值。
- 日志按实测完整键映射、优先解析 JSON、保留阻断原因和审计输出的方向正确。A01、A02 表明仍需逐消费者验收。

以上是当前差异与定向测试支持的判断，不是对全部后端业务链路的担保。

### 4.4 保留项与证据缺口不能混为一类

兼容枚举、权限码、原始审计值是明确保留项；默认公钥的来源/用途、最终邮件、其他报告分支和名单语义则是待核实项。旧页面存在某公钥只能证明来源，不能证明当前环境应继续默认使用它；不能擅自换密钥。

两份 Excel 的检查结果属于原文档记录，本轮未重新解包验收，不重复计为新增验证。未覆盖邮件或其他报告不应被写成已通过，也不能未经用户确认将其排除在清理范围之外。
