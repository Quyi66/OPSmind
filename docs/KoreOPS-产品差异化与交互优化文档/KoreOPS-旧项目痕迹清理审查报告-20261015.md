## 3. 需要修复的问题

### R01 · P1：关闭详情可能中断“跳过并安装”，留下缺少继续入口的任务

**归属：未提交的 D1 包集追踪改动。**

证据：

- [InstallTaskDetailDialog.vue](../src/modules/patches/components/InstallTaskDetailDialog.vue)，约 481–503 行：`handleSkipPreCheck` 在跳过请求返回后检查 `taskSession`；会话已变化时直接返回，不发送 `executeInstallTask`。
- 同文件约 226、376–378 行：操作区仅在 `PRE_CHECK_FAILED` 且满足门禁时提供，未提供从 `PRE_CHECK_DONE` 继续安装的入口。
- [包集接口约定](./patch-package-set-oneclick-api.md)，约 165–167 行：失败后跳过需要前端显式调用安装接口，自动接续仅适用于首次预检查全部通过。
- 历史测试 `tests/modules/patches/PackageSetTracking.test.js`（D1 撤销时已删除），当时约 218–230 行：测试明确断言跳过请求发出后关闭详情，不再追加安装请求，但未验证重新打开后的恢复能力。

触发过程：

1. 任务预检查失败，用户确认“跳过并执行安装”。
2. `skipPreCheck` 已发出，用户在响应返回前关闭详情或切换任务。
3. 服务端完成跳过，按接口契约将任务置为 `PRE_CHECK_DONE`。
4. 前端因会话变化返回，不再调用安装接口。
5. 重新打开详情时，不满足失败态操作区的显示条件，缺少继续安装入口。

**影响：** 已确认的操作可能只完成第一步，任务停在中间状态。该判断由前端控制流与现有接口契约支持，尚未通过线上真实任务验证。

**建议：** 区分“忽略旧响应对当前界面的更新”和“中断已经确认的业务操作”。保证已确认的两步操作完整结束，或补齐受权限、时间及状态门禁约束的恢复入口。回归测试需要覆盖关闭、切换、第二步失败以及重新打开后的处理。

## 4. 清理标准及遗留项

### 4.1 技术标识需要保留业务识别兜底

普通对象 ID、运行 ID、脚本路径本身不等于旧项目品牌痕迹。降低其展示优先级可以改善阅读，但不应让用户失去识别或排查对象的能力。

- [CronJobTable.vue](../src/modules/automation/components/job/components/CronJobTable.vue) 移除任务 ID 后，同名且其他可见字段相同的任务缺少直接区分手段；删除等确认又主要依赖名称。
- [InstallTaskDetailDialog.vue](../src/modules/patches/components/InstallTaskDetailDialog.vue) 约 167–177 行，在名称解析失败时，多个预检查对象都显示“主机名称未返回”，需要逐一悬停才能辨认标识。

这是识别能力的设计风险，不代表必须恢复所有技术列。建议在缺少可读名称或遇到同名对象时，保留短标识、明确兜底或可直接访问的详情；完整原始值仍供排查使用。

### 4.2 硬编码旧来源默认公钥尚未核实

[DeviceManageDialog.vue](../src/modules/asset/components/automation/DeviceManageDialog.vue) 约 271–272 行硬编码了一段带 `demo@oplus-dev` 注释的默认公钥。该值绑定到用户可编辑的 SSH 公钥表单，并可进入提交参数，不只是代码注释或无效字符串。
