### 共享轮询应先处理

1. [useJobPolling.js:136](../src/composables/useJobPolling.js#L136) 将所有非 WAITING/RUNNING、非 SUCCESS/COMPLETED、非 FAILED/ERROR 的状态当成功。单条 ERROR 数组未解包后 status 为 undefined，也进入这里；INTERRUPTED 同样提示成功。仓库 [jiesuan-sync-frontend-api-changes.md](./jiesuan-sync-frontend-api-changes.md) 已记录 INTERRUPTED 及 PAUSED 等状态语义，不能默认完成。
2. [useJobPolling.js:222](../src/composables/useJobPolling.js#L222) 的简单 pollJobStatus 只判断 FAILED，标准 ERROR 对象不触发 onError，只触发 onComplete，无错误提示。本问题不是成功toast，但会造成失败反馈缺失。
3. 实际依赖覆盖软件主机概览/详情、Sudo扫描/授权/改密/策略、用户任务、Linux部分扫描/安装、Windows扫描；简单 pollJobStatus 被资产清单和资产总览连通性检查使用。修共享层前必须保护 pollVersion、目标/窗口代次、stop/unmount、每个消费者的完成条件。useUserDialogTask 的 finish 会再验证 SUCCESS/COMPLETED，因此共享 onSuccess 误触发不等于其自身也会成功，不可按消费者数量直接扩算缺陷。
4. 本轮没有修改共享轮询，更没有借此恢复 Windows 优化或执行真实任务。
