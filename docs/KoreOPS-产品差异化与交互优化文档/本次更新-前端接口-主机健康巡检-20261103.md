# 主机健康巡检 — 前端接口

前缀：`/sjxy-console/secops`，均需登录（带 `Authorization`）。

平台每天 02:00 自动对全部纳管 Linux 主机巡检一次（cron 可用 `sjxy.secops.health.cron` 覆盖），
也可在页面手工触发。巡检内容包括资源利用率、近 24 小时系统日志报错、服务与安全状态，结果按满分 100 打分并给出风险提示。

## 状态取值

| status | 含义 | 建议颜色 |
|---|---|---|
| HEALTHY | 健康，全部检查项正常 | 绿 |
| WARNING | 有告警项 | 黄 |
| CRITICAL | 有严重项 | 红 |
| UNREACHABLE | 主机不可达或巡检脚本执行失败（0 分，不计入平均分） | 灰 |
| UNCHECKED | 纳管后还没巡检过 | 浅灰 |

检查项 `level`：`NORMAL` / `WARNING` / `CRITICAL`。

## 1. 健康概览

`GET /api/secops/v2/health/summary`

```json
{
  "counts": { "HEALTHY": 120, "WARNING": 8, "CRITICAL": 2, "UNREACHABLE": 3, "UNCHECKED": 1 },
  "avgScore": 93,
  "latestRun": {
    "runId": "857466432b354fe4b5c1b6d0e23634fb",
    "status": "COMPLETED",
    "hostTotal": 134, "hostChecked": 133,
    "message": null,
    "startedAt": "2026-11-03T02:00:00", "finishedAt": "2026-11-03T02:12:40"
  }
}
```

- `counts` 里没有出现的状态即为 0。
- `latestRun.status`：`RUNNING`（巡检中）/ `COMPLETED` / `FAILED`；从未巡检过时 `latestRun` 为 `null`。
- `message` 非空表示部分批次未带回结果，这些主机保留上次结果。

## 2. 主机健康列表

`GET /api/secops/v2/health/hosts?status=&keyword=&page=1&size=20`

- `status` 可选，取值见上表；`keyword` 按 IP / 主机名模糊匹配；`size` 上限 200。
- 默认排序：CRITICAL → UNREACHABLE → WARNING → HEALTHY → UNCHECKED，同状态按分数从低到高。

```json
{
  "total": 1,
  "list": [{
    "hostId": "IMmtvf",
    "hostIp": "192.168.1.144",
    "hostname": "144",
    "os": "Kylin Linux Advanced Server V11 (Swan25)",
    "score": 90,
    "status": "WARNING",
    "checkTime": "2026-11-03T02:23:40",
    "risks": [
      "时钟同步 未同步：系统时间未与 NTP 同步，可能导致日志时间错乱、证书校验和集群通信异常",
      "SSH失败登录(24h) 8 次：失败登录较多，可能存在暴力破解，建议限制来源 IP"
    ],
    "items": [
      { "name": "CPU使用率", "value": "0.1%", "level": "NORMAL" },
      { "name": "时钟同步", "value": "未同步", "level": "WARNING" }
    ]
  }]
}
```

- `risks`：风险提示，可直接展示；健康主机为空数组。
- `items`：全部检查项，用于详情展开；主机没有对应能力时（如无 systemd）该项不出现。
- UNCHECKED 主机的 `score` / `risks` / `items` / `checkTime` 为 `null`。

## 3. 立即巡检

`POST /api/secops/v2/health/run`

- body 可选：主机 id 数组 `["IMmtvf", "..."]`，用于"对选中主机重新巡检"；不传即巡检全部 Linux 主机。
- 返回 `{"runId": "...", "message": "巡检已下发"}`；已有巡检在执行（6 小时内）或没有主机时 `runId` 为 `null`，`message` 说明原因。
- 巡检是异步的，建议轮询 `summary` 的 `latestRun.status` 直到不是 `RUNNING` 再刷新列表。

## 检查项与扣分

| 检查项 | 告警 / 严重 | 扣分 |
|---|---|---|
| CPU使用率 | ≥80% / ≥95% | 10 / 20 |
| CPU IO Wait | ≥20% / ≥50% | 5 / 10 |
| 内存使用率 | ≥80% / ≥95% | 10 / 20 |
| Swap使用率 | ≥20% / ≥80% | 5 / 10 |
| 磁盘使用率（最高分区） | ≥80% / ≥90% | 10 / 25 |
| inode使用率（最高分区） | ≥80% / ≥90% | 5 / 15 |
| 磁盘IO利用率（最忙磁盘） | ≥80% / ≥95% | 5 / 10 |
| 只读文件系统 | 有即严重 | 25 |
| 系统负载（1 分钟 / 核数） | ≥1 / ≥2 | 5 / 15 |
| 文件描述符使用率 | ≥80% / ≥95% | 5 / 15 |
| TCP连接数 | ≥10000 / ≥30000 | 5 / 10 |
| 时钟同步 | 未同步为告警 | 5 |
| 僵尸进程 | ≥1 / ≥50 | 5 / 10 |
| 失败的系统服务 | ≥1 / ≥5 | 5 / 15 |
| SSH失败登录(24h) | ≥5 / ≥100 | 5 / 10 |
| 系统错误日志(24h) | ≥100 / ≥1000 条 | 5 / 10 |
| 内存溢出(OOM) | 有即严重 | 20 |
| 磁盘I/O/文件系统错误 | 有即严重 | 25 |
| 内核异常（Call Trace / 软锁死 / 段错误 / 硬件错误） | ≥1 / ≥10 | 10 / 20 |

分数 = 100 − 扣分（最低 0）；状态取最差检查项。
