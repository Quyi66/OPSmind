## 开发与检查约定

当前启用资源位于 `src/locales/{zh-CN,en-US}`，命名空间为 `common`、`auth`、`navigation`、`hostUser`、`selection`、`execution`、`home`、`profile`、`about`、`ai`、`admin`、`asset`。中英文的 key 和参数须一致。语言入口、加载白名单及词条检查范围均从 `src/core/i18n/locales.js` 的注册表派生。

```js
import { t } from '@/core/i18n'
import { message, messageRef } from '@/core/i18n/feedback'

// 模板或 computed 中求值，避免将翻译后的文本固化为状态。
const notice = messageRef('')
notice.value = message('auth.required')

// 后端原始内容直接存入，不会被转换或猜测翻译。
notice.value = backendMessage

// 一次性提示在创建时使用当前语言。
ElMessage.success(t('auth.success'))
```

- 新增词条同时提交中英文版本；请求字段、状态码、操作类型和权限码不翻译。
- 复用旧 key 时核实其当前引用和原始消息格式，避免将后端中文原文当成本地 key。
- `npm run i18n:check` 检查已注册语言的 key、插值参数、消息编译语法和 JSON 重复键，并检查显式导入的 `t` / `message` 字面量引用及独立 AI 生成物，不扫描未启用的预留语言。源码检查用于找缺词，不代替路由调用链确定迁移范围。
- 修改 `ai.json` 或语言注册表后，运行 `npm run i18n:sync-ai` 更新 `public/aiops-i18n.js`。
- 测试位于 `tests/core/i18n`，以及公共页面、资产/健康度、主机用户、设备选择器、执行结果/日志和共享轮询的交互测试中。
- 本批未运行生产构建、截图或截图级视觉确认；验证使用针对性 Vitest、Vue 脚本/模板静态语法检查、差异审查及 ESLint 基线比较。

## 本次评审核查与修正

- 已还原 `vite.config.ts`、路由 `base.js` 和 `TagsView/index.vue` 中混入的纯格式改动。Vite 配置只保留三个国际化编译标志。

- 仓库、桥接层和配置中未发现 `elLocale` 注入方或对外接口声明，已删除冗余字符串 key 的 provide；Element Plus 继续通过 `App.vue` 的 ConfigProvider 获取当前语言。
- 旧词库请求失败会记录模块、URL 和异常；首次使用旧词库后，有效语言变化会重试失败模块。成功和正在加载的模块保持缓存，重试不阻塞切换，也不增加自动循环重试。警告仍遵循项目既有生产 console 清理策略，不等同于新增线上监控上报。
- 标签页缓存的兼容边界：有标题 key 且标题与元数据一致时可翻译；没有匹配元数据的历史文案无法与自定义标题可靠区分，保留原文。旧版本文案即使仍是中文也不自动覆盖，可关闭该标签后从当前路由重新打开。已补充有/无元数据的历史缓存测试。
- `typescript` 原已是直接开发依赖；本次将 `@intlify/message-compiler` 同样声明为直接开发依赖，同步锁文件，不升级已锁定包。
- 已删除无使用方的 `numberFormatter`，为未启用的繁体匹配分支补上扩展注释。原生语言 select 的视觉统一列为后续优化，本批保留现有交互。
