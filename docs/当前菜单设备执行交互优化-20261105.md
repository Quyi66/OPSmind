# 当前菜单中的设备执行交互优化

本轮以 `menu.config.js`、`module-nav.config.js` 及对应模块导航为范围依据，排除隐藏的安全管理菜单、旧主机概览独立路由和工作台中未显示的命令面板。之前的迁移记录包含历史入口，不代表本轮的页面验收范围。

## 逐项验收

| 当前页面 | 优化内容 | 验收操作与预期 |
| --- | --- | --- |
| 资产管理 → 连通巡检（`/acm/exception`） | 共用设备选择器分别统计设备、分组、标签和其他选择 | 连通性检查、信息数据采集仍直接打开选择器；空选择不能执行；提示间距保持 8px，“一键全选”保持原属性及朴素样式。 |
| 补丁漏洞 → Linux 主机概览（`/patches/machineScan`） | 已明确目标时展示轻量确认 | 行内扫描仅显示当前主机，批量扫描显示已选主机；取消不提交；“更改设备”保留预选并打开完整选择器；只在最终“开始扫描”时请求；提交失败保留目标。通用“扫描补丁”仍直接打开完整选择器。 |
| 补丁漏洞 → Windows 主机概览（`/patches/windowsVulnerability`） | 共用运行结果中突出失败目标和步骤 | 扫描提交成功后打开原有结果窗口；失败时显示后端明确标记的失败/不可达目标、步骤和错误原文；可展开完整字段、复制原始错误、查看完整日志。 |
| Linux 补丁管理 → Yum仓库 → YUM源清单（`/yum-repo/yumManage`） | 保留最近提交任务的进度入口 | 扫描成功提交后，列表顶部出现“查看进度与结果”；关闭结果窗口后可重新查看，不会再发起扫描请求。入口保留到本页面实例销毁；后续成功提交更新为最近任务。 |
| Linux 补丁管理 → Yum仓库 → 配置下发（`/yum-repo/repos`） | 配置前展示仓库名称与目标摘要；补充空状态入口 | 基准仓库和自定义仓库“配置到主机”均显示仓库名称、当前已选目标类型；基准仓库成功读取为 0 条时显示准备条件，可转到“基准主机”页签；读取错误时保留原错误提示。 |
| 自动化管理 → 命令与运维工具（`/cmd/list`） | 执行前展示命令原文 | 单个或多个命令的直接执行窗口展示已发布 `command` 字段；长内容可展开，缺失时明确显示“未提供命令内容”；创建运维工具表单继续保留。 |
| 主机用户管理 → 用户列表（`/users/users`） | 进度中展示目标、状态和结果入口 | 扫描提交后展示目标摘要/明细、执行状态及“查看进度与结果”；运行 ID 收入“执行记录”详情；查看结果不重新提交；未知结果仍禁止重复下发。 |

## 错误展示约定

- 不新增基于英文关键字的原因推测或翻译对照表。
- “失败”“不可达”等中文标识来自后端明确字段；未知状态和错误正文保留原文。
- 失败目标的消息保留换行。原始详情保留全部返回字段，复制功能复制完整原文/完整 JSON，不复制截断文本。
- 原有明确错误代码的展示逻辑继续保留；新增原始错误区不会覆盖后端信息。
- 失败目标较多时分批展示，完整日志入口始终可用（前提是后端已返回日志）。

## 接入与验证

- 共用选择器新增 `context` 作用域插槽，通过 `selection` 提供当前全部选择，用于展示业务摘要；不会更改请求参数。
- `DeviceSelectionSummary` 分开统计显式设备、分组、标签和其他选择；分组与标签按执行时成员展开，不相加猜测最终设备数量。
- Linux 与 YUM 扫描的明确 `FAILED`/`ERROR` 响应即使携带运行 ID，也不会当作提交成功。
- 基准仓库测试环境仍无数据，真实配置提交仍按“无数据”记录；未创建仓库测试数据。
- 代码阶段以交互测试、静态检查和差异审查验证，不运行生产构建，不做截图级验证。新增交互已于 2026-11-06 完成浏览器实测，详见[当前菜单浏览器实测记录](./当前菜单设备执行交互-浏览器实测-20261106.md)。此前迁移阶段的浏览器记录仍保持独立。
- 回归结果：12 个测试文件、203 项测试全部通过。覆盖取消/更改目标、重复提交保护、业务失败、结果重新打开、错误原文及复制、命令预览、分类型计数和基准仓库空态。
- 新增及其余修改文件的 ESLint 错误检查通过；`LinuxPatchScanPage.vue` 原有 4 个静态错误与暂存基线一致，无新增。`git diff --check` 通过。
