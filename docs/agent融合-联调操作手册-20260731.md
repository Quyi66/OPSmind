# KoreOps Agent 联调操作手册

平台 `192.168.1.162`（`sjxy:3.6.1` / `opsmind-web:2.1.7`） · 执行器 `192.168.1.163`（ata）
接口清单见 `KoreOps-Agent-前后端联调任务单.md` §7

> token 一律不进 git / 群聊 / 截图。

**起点：** 签发、静态入口、执行器通道均已就绪，缺一台测试端点。从第 2 步开始做。

---

## 0. 变量

```bash
BASE=https://192.168.1.162/sjxy-console
JWT=<管理员JWT>        # 浏览器登录后 F12 → 任一 /sjxy-console/ 请求 → Authorization 头
TENANT=<TenantId>      # 同一请求的 Tenant-Id 头
```

端点机要求：Linux + systemd + root + 可达 `162:443`。python3 可无（脚本自建 venv）。暂无 Windows 包。

## 1. 基线自检

**作用：** 确认环境没退化。任一条不符预期，先照 §8 排错，不要往下走。

```bash
# 静态入口
curl -sk -o /dev/null -w "install.sh -> %{http_code}\n" $BASE/agent/install.sh
# 期望 200

# 无 token 注册
curl -sk -X POST $BASE/agent/api/agent/register \
  -H "Content-Type: application/json" -d '{"clientId":"probe"}'
# 期望 {"errorCode":"AGENT_AUTH_FAILED","ok":false,"message":"缺少 clientId 或 token"}
```

```bash
# 执行器通道（在 163 上）
ssh root@192.168.1.163
cat > /tmp/hosts <<'EOF'
[agenthosts]
probe-nonexistent ansible_connection=oplus_agent oplus_agent_client_id=probe-nonexistent oplus_relay_url=https://192.168.1.162/sjxy-console/agent/api/agent
EOF
cd /tmp && ansible -i hosts agenthosts -m raw -a 'id'
# 期望 errorCode=AGENT_OFFLINE
```

## 2. 签发 token

**作用：** 换取一次性安装凭据；`maxUses=1` 顺带验证「用尽后拒绝」。

```bash
curl -sk -X POST "$BASE/cmdb/api/cmdb/agent/enrollment-token" \
  -H "Authorization: Bearer $JWT" -H "Tenant-Id: $TENANT" \
  -H "Content-Type: application/json" \
  -d '{"ttlMinutes":60,"maxUses":1,"remark":"联调-端点1-20260731"}'
```

期望返回 `token` + `installCommand`。**检查 `installCommand` 是 `https://`，且 `--server` 只到 `/sjxy-console`**（带 `/agent/api/agent` 会拼成重复路径）。

需要角色 `ROLE_ADMIN`/`ROLE_PRIVUSER`/`ROLE_DEVELOPER`/`ROLE_FREE` 之一。

## 3. 端点安装

把上一步的 `installCommand` 原样贴到端点执行（root）：

```bash
curl -fsSL https://192.168.1.162/sjxy-console/agent/install.sh | sudo sh -s -- \
  --token <enrollment_token> --server https://192.168.1.162/sjxy-console
```

端点自检：

```bash
systemctl is-active koreops-agent                      # active
ls -l /etc/koreops-agent/state.json                    # -rw------- 且含 clientToken
grep REQUESTS_CA_BUNDLE /etc/systemd/system/koreops-agent.service
# 作用：证明自签 CA 已生效。https 环境缺这行，Agent 必然连不上
journalctl -u koreops-agent -n 40 --no-pager           # 无 TLS / 401 报错
```

平台侧确认：

```bash
curl -sk "$BASE/cmdb/api/cmdb/agent/pending" \
  -H "Authorization: Bearer $JWT" -H "Tenant-Id: $TENANT"
# 期望 hostId=null、status=online；记下 clientId，下一步用

curl -sk "$BASE/cmdb/api/cmdb/agent/enrollment-token/<tokenId>" \
  -H "Authorization: Bearer $JWT" -H "Tenant-Id: $TENANT"
# 期望 status=exhausted, usedCount=1
```

## 4. 绑定资产

**作用：** 建立 `hostId ↔ clientId`，同时后端写入 `cmdb_ansible_config.param`——这是执行通道的入口，不绑定则任务仍走 SSH。

```bash
curl -sk -X POST "$BASE/cmdb/api/cmdb/agent/bind" \
  -H "Authorization: Bearer $JWT" -H "Tenant-Id: $TENANT" \
  -H "Content-Type: application/json" \
  -d '{"clientId":"<clientId>","hostId":"<CMDB主机id>","mode":"local"}'
```

`mode=local` 指 Agent 装在目标机本机；跳板场景用 `/bind-gateway` 并带 `targetIp`。

```bash
curl -sk "$BASE/cmdb/api/cmdb/agent/host-info?hostIds=<hostId>" \
  -H "Authorization: Bearer $JWT" -H "Tenant-Id: $TENANT"
# 期望 connectionType=koreops_agent, agentStatus=online
```

```sql
-- 确认连接参数已写入
SELECT name, param FROM sjxy.cmdb_ansible_config WHERE name = CONCAT('agent-conn:', '<hostId>');
```

## 5. 执行通道

在 163 上，把 §1 的 `/tmp/hosts` 里 clientId 换成真实值：

```bash
ansible -i hosts agenthosts -m raw -a 'id'    # 期望 rc=0
ansible -i hosts agenthosts -m ping           # 期望 SUCCESS => {"ping": "pong"}
```

**作用：** `raw` 只走 exec 通道，`ping` 会先 put 模块文件再执行。分两次跑，是为了在失败时立刻区分是 exec 还是 put 出问题。

再从平台对该主机发起 Ansible 任务，确认任务详情的执行通道为 `koreops_agent`，且 163 的 rolling-log 里该主机不再出现 ssh 连接失败。

## 6. 业务闭环

平台对该主机发起补丁扫描，确认结果落正式表：

```sql
SELECT run_id, host_id, scan_timestamp FROM sjxy.patchops_curr_machine_scan
WHERE host_id = '<hostId>' ORDER BY scan_timestamp DESC LIMIT 5;
```

**红线：** 必须进 `patchops_*`。旧 Relay demo、JSONL 文件不算验收证据。

扫描通过后再验安装、回滚。`capabilities` 里的 `rollback` 只表示通道能执行回滚指令，不等于补丁回滚业务已通，分开验收。

## 7. 故障演练

| 演练 | 操作 | 期望 |
|------|------|------|
| 断网恢复 | 端点 `iptables -I OUTPUT -d 192.168.1.162 -p tcp --dport 443 -j DROP`，2 分钟后删除 | 持续重试不崩；恢复后复用原 clientToken 自动重连，无需重装 |
| **重启不重复执行** | 下发耗时指令，执行中 `systemctl restart koreops-agent` | **重点**：已上报 cmdId 集合只在进程内存（`_reported` 仅 process lifetime），重启后有重复执行风险 |
| clientToken 失效 | 改坏端点 `state.json` 后重启 | 回落用 enrollment 重注册；enrollment 也失效时应明确报错而非静默重试 |
| enrollment 过期 | 用已 `exhausted` 的 token 装第二台 | 失败并返回 `ENROLL_TOKEN_INVALID` |
| web 重建后入口仍在 | 162 上 `docker compose -f /opt/sjxy/docker-compose.yml up -d --force-recreate sjxy-web` | `install.sh` 仍 200 |

## 8. 排错速查

### 先分清两种 401

| 返回体 | 含义 | 处置 |
|--------|------|------|
| `{"timestamp":"…","status":401,"error":"Unauthorized"}` | **Spring 层**：运行包里没有 Agent 代码或 shiro 规则，请求没进业务逻辑 | `docker ps` 确认 `sjxy` 镜像 ≥ `3.6.1` |
| `{"ok":false,"errorCode":"AGENT_AUTH_FAILED",…}` | **业务层**：正常，控制器活着，只是没带 token | 带上 `X-Agent-Token` |

### 其余

| 现象 | 原因 | 处置 |
|------|------|------|
| `install.sh` 401 | nginx 静态卷丢了 | 确认主 `docker-compose.yml` 有 `koreops-agent:ro` 卷、web 镜像 `2.1.7`。**别写进 `-f` override，重建即丢** |
| `ENROLL_TOKEN_INVALID` | token 用尽/过期/已吊销 | 重新签发 |
| ansible `CERTIFICATE_VERIFY_FAILED` | `REQUESTS_CA_BUNDLE` 未生效。ansible 跑 python3.12，用自带 certifi，**无视系统信任库** | 查 `/opt/sjxy/config.sh`，并确认改后重启过 `sjxy-agent` |
| ansible `AGENT_AUTH_FAILED relay token 校验失败` | 执行进程没有 `AGENT_RELAY_INTERNAL_TOKEN` | 同上，改完必须重启，子进程才继承 |
| ansible `unable to load connection plugin` | 插件不在生效目录 | 必须放 `/etc/ansible/connection_plugins`（`ansible.cfg` 的 `./connection_plugins` 相对**配置文件目录**，不是 CWD） |
| ansible `AGENT_OFFLINE` | Agent 离线或 clientId 写错 | 查 `/pending` 的真实 clientId；端点 `systemctl status koreops-agent` |
| 绑定后仍走 SSH | 连接参数没生效 | 查 `cmdb_automation` 是否指向 `agent-conn:<hostId>`、`param` 是否含 `ansible_connection=oplus_agent` |
| `DISPATCH_TIMEOUT` | Agent 取了指令未回传 result | 核对 `cmdId`，看端点日志 |
| 端点起不来 | — | `journalctl -u koreops-agent -n 50 --no-pager` |

内置阈值（判断"等多久算异常"）：长轮询 30s → 204；心跳超时判离线 90s；指令结果超时 120s；状态刷库 30s。

## 9. 联调后清理

```bash
# 平台：解绑 + 吊销
curl -sk -X POST "$BASE/cmdb/api/cmdb/agent/unbind" \
  -H "Authorization: Bearer $JWT" -H "Tenant-Id: $TENANT" \
  -H "Content-Type: application/json" -d '{"hostId":"<hostId>"}'
curl -sk -X DELETE "$BASE/cmdb/api/cmdb/agent/enrollment-token/<tokenId>" \
  -H "Authorization: Bearer $JWT" -H "Tenant-Id: $TENANT"

# 端点：卸载
systemctl disable --now koreops-agent
rm -f /etc/systemd/system/koreops-agent.service && systemctl daemon-reload
rm -rf /opt/koreops-agent /etc/koreops-agent /var/log/koreops-agent
```

解绑只清关联，`/pending` 仍会留该 clientId（暂无删除待纳管 Agent 的接口，见任务单 §7.4）。
