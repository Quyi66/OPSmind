从 `feature/frontend-i18n` 的 `af6a9e23` 开始，起始工作区干净。本轮修改留在工作区。本地开发服务和已登录专用 Chrome 会话可用，二级采集显式传入 `--no-screenshots`，使用简体中文、英文及 1440 / 1920 CSS 像素宽度。

## 入口和取样

| 入口 | 实际调用链和覆盖范围 |
| --- | --- |
| Windows 主机概览 | `WindowsPatchOverviewPage` 的 submitted 回调是独立 `WinPatchTaskDetailDrawer` 的唯一入口。当前扫描、单机安装和批量安装处理函数都传 `openDetail: false`，在用安装、回滚向导也只有创建任务后才进入执行详情。独立详情的英文状态列和长错误说明按代码及组件测试处理，真实详情未取得。 |
| `/patches/logs` | 按近一年及 Windows 扫描、安装、回滚分类查询历史，打开已有状态标签对应的 `ExecuteResultDialog`。这些是历史执行结果。 |
| `/acm/automation` | 批量录入 → `DeviceManageDialog` 的密码和 SSH 两页。账号所在环境使用标准执行节点，真实 AAP 表单未覆盖。 |
| `/acm/info` | 设备行编辑 → `AssetEditDialog`。临时勾选后打开已选设备、加标签、加入分组，结束后恢复原勾选。 |
| `/acm/data` | 分组及标签各自的新建、编辑弹窗。 |
| `/cac/results` | 检查结果 → 主机列表 → 检查项计数 → `HostDetailDialog`，查看六种筛选及多项 `CheckItemDetailDialog`。记录行数和已有输出长度。 |
| `/uam/user` | 创建和编辑 → `UserEditDialog`，检查展开后的基本信息、改密字段、角色和应用页。 |
| `/gfs/fileLibrary` | 文件名称 → `FileContentDialog`；在库中按界面浏览现有目录。 |
| `/gfs/scriptLibrary` | 通过脚本库查看现有文件，复用 `FileContentDialog`。 |
| `/jao/jobs` | 新建脚本工具草稿 → 多选文件 → `FileSelectorDialog` 和文件预览。勾选只在草稿内，关闭时丢弃。 |
| `/run-records/logs` | 查询近一年命令和 REST 记录，只有存在记录时才打开结果。流程类型在当前过滤器中未启用。 |

## 已确认问题和修改

- 新建标签的英文名称提示约裁切 34px。缩短提示，保留中英文字符、数字、下划线和普通空格的校验规则及简体中文文案。编辑标签和设备加标签复用这条提示。
- 批量凭据录入的 AAP 实例组标签进入中英词库。模拟 AAP 接口验证切换语言后保留已选实例组原名，只查询一次，表单未提交。
- Windows 任务详情中 `Partially succeeded` 需要比现有 100px 状态列更多空间。英文状态列改为 168px，筛选框由 140px 增至 180px。英文详情允许纵向滚动及长错误文本换行，简体中文保持原宽度和样式。定向用例核对筛选值、原始错误和切换语言期间的调用次数。
- 文件库的静态文件元数据返回缺少仓库类型、文件路径为 `null` 的占位地址。四组真实预览均收到 404。文件查看组件识别该地址并复用现有的回退逻辑，以原始仓库类型、仓库及文件路径读取内容。正常服务端地址仍直接使用。
- 二级脚本采集同源 HTTP 状态和请求失败路径。出错的组合保留错误状态，零采集状态直接判失败。报告不记录请求体、查询参数、认证信息和表单输入值。
