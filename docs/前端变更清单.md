# Agent 纳管精简 — 前端变更清单（2026-09-10）

后端接口已收敛为 6 个（详细字段见 `docs/agent精简方案-接口文档-20260910.md` §2）。本清单只列前端要改的点，按"删 / 改 / 加"分三组。后端已部署到 `192.168.1.150`（`sjxy:3.8.4`），可直接联调。

基址：`/sjxy-console/cmdb/api/cmdb/agent`。业务错误一律 `400 {errorCode, message}`。

## 1. 删（接口已下线，请求会 404/405）

| 旧接口 | 替代 |
|---|---|
| `GET  /enrollment-token/{id}` | `GET /pending?tokenId=`，响应里的 `token` 段 |
| `POST /bind-gateway` | `POST /bind` + `"mode":"gateway"` |
| `POST /sync-ip` | 删除按钮"同步资产 IP"。`host-info.ipMismatch` 仍返回，只作提示 |
| `GET  /route-mismatch` | 删除"路由错位清查"页/入口。下发时按绑定实时派生连接参数，错位不再可能发生 |

## 2. 改

### 2.1 凭证：`POST /enrollment-token` → `POST /enroll-tokens`；`DELETE /enrollment-token/{id}` → `DELETE /enroll-tokens/{id}`

- 请求多一个可选 `targetOs`（`linux` 默认 / `windows`），决定返回哪条安装命令。`ttlMinutes` 默认 1440，`maxUses` 默认 0（不限次）。
- 响应删掉 `installCommandLinuxHttps / installCommandLinuxHttp / installCommandLinuxCa / installCommandWindows` 四个字段，**只读 `installCommand`**（一条，可直接复制）。新增 `remainingUses`（`maxUses=0` 时为 `null`）。
- 生成凭证页去掉 https/http/CA 三选一 tab，只保留"Linux / Windows"切换（切换即重新调 `enroll-tokens`，或一次生成两张）。

### 2.2 等待上线：`GET /pending` 返回从数组变为对象

```json
{ "token": { "id", "status", "remainingUses", "expiresAt" },   // 传了 tokenId 才有
  "agents": [ { "clientId", "hostname", "ip", "os", "agentPlatform", "agentVersion",
                "capabilities", "agentStatus", "registeredAt", "lastSeenAt",
                "matchedHosts": [ { "hostId", "hostname", "ip", "ciType", "matchedBy" } ] } ] }
```

- 轮询建议 3~5s；`token.status !== 'active'` 或 `token.remainingUses === 0` 时停止轮询并提示重新生成。
- 用 `matchedHosts` 渲染"候选资产"（按 IP / 主机名命中的已有 CI，只是候选，后端不自动绑）。0 条默认勾"新建资产"。
- 按平台区分图标/按钮用 `agentPlatform`，不要解析 `os` 字串。

### 2.3 绑定：`POST /bind` 请求增 `newHost / mode / targetIp`，响应结构变化

- 原 `{clientId, hostId}` 仍可用（绑到已有资产）。
- 新建资产并绑定：`{clientId, newHost: {}}`（全部字段可空，后端用 Agent 上报的 hostname/ip/os 建档；CI 类型按 `agentPlatform`）。可显式传 `newHost.{hostname, ip, ciType, groupIds}`。**向导第 3 步不再跳转"新增主机"页**。
- 跳板：`{clientId, mode:'gateway', targetIp, hostId | newHost}`。
- 响应从绑定实体变为 `{hostId, clientId, agentMode, targetIp, agentStatus, hostCreated}`；成功后跳 `hostId` 详情。
- 错误码：`HOST_ALREADY_BOUND / CLIENT_ALREADY_BOUND / HOST_NOT_FOUND / AGENT_OFFLINE / PLATFORM_SELF`。以下旧码不再出现：`PLATFORM_SELF_BIND`、`ENROLL_TOKEN_EXPIRED / EXHAUSTED / USED / REVOKED`（统一 `ENROLL_TOKEN_INVALID`，`message` 里带 `[reason=…]`）、`ROUTE_MISMATCH`。

### 2.4 主机 Agent 信息：`GET /host-info` 字段

- `lastReportedIp / lastReportedAt` → 删除；新增 `agentIp`（local = Agent 最近上报 IP，gateway = targetIp，即命令实际落点）。
- `agentStatus` 只有 `online / offline`（SSH 主机为 `null`），不再有 `unknown`。
- 其余字段不变：`connectionType / agentClientId / agentMode / targetIp / agentVersion / capabilities / os / agentPlatform / cmdbIp / ipMismatch / lastSeenAt`。
- Windows 补丁主机列表（`/secops/api/secops/win/hosts`）里附带的 Agent 字段同上。

### 2.5 下发被阻断时的提示

任务下发（扫描 / 安装 / 回滚 / 采集 / 连通性）若目标含平台自身地址，后端整批拒绝，`message` 以 `[AgentRoute] 本次下发已阻断，N 台目标不可执行：` 开头、逐行 `- [PLATFORM_SELF] ciId=… (hostname) ip=… 说明`。前端按行展示即可，不要截断。离线 Agent 不整批拒绝：该主机在运行记录里单台 `AGENT_OFFLINE` 失败（同 SSH 不可达），所以前端仍要按 `host-info.agentStatus` 预先禁按钮。

## 3. 加（第二批：操作流程精简，2026-09-10 下午）

目标是把"人要跨机器、要等、要挑"的步骤拿掉。四个新接口，两处页面改法。

### 3.1 主机列表：按钮"安装 Agent"（已录资产，平台推装）

`POST /sjxy-console/cmdb/api/cmdb/agent/install` body `{ "hostIds": ["...", "..."] }`

```json
{ "runId": "xxxx", "submitted": ["h1","h2"], "skipped": { "h3": "已由 Agent 纳管（cid…），如需重装先解绑" } }
```

- 只对 `host-info.connectionType !== 'agent'` 的行显示；Linux/Windows 混选可以，后端一个 run。
- 平台用资产已有 SSH/WinRM 凭据登上去装 Agent，**用户不用登目标机、不用复制命令、不用挑资产**：Agent 注册即绑到该资产。
- 点完后轮询 `GET /host-info?hostIds=`，`agentStatus` 变 `online` 即成功（一般 1~3 分钟）；`runId` 可链到作业记录看失败原因（凭据错 / 不可达 / 安装失败逐台列在结果里）。
- 400 `{message}`：`hostIds` 为空；`skipped` 里逐台给原因，不算错误。

### 3.2 生成凭证页：一行命令 + 预绑定

`POST /enroll-tokens` 请求新增可选 `hostId`：

- 传了 `hostId`（从资产行"生成本机安装命令"进来）：凭证一次性、`targetOs` 按资产类型自动取，Agent 注册即绑到这台，**不进待处理列表**。
- 不传（通用凭证，给新机器）：注册后按上报的主机名 / IP / OS 自动建档并绑定。平台**不按 IP 匹配已有资产**（管控机 IP 不固定）；要对到已有资产只走上一条。

响应新增 `bootstrapUrl`、`hostId`、`clientId`；`installCommand` 现在是**一行**：

- `clientId`（`kops-…`）是平台签发的这台机器的 Agent 身份，单次凭证才有（多次凭证 `null`）。它已写进引导脚本，前端不用往命令里拼；资产行签发时可在页面上显示"Agent 身份：kops-…"，装好后 `host-info.agentClientId` 就是它。

```
Linux   : curl -fsSLk -o /tmp/koreops-i.sh 'https://<平台>/sjxy-console/agent/api/agent/i/<token>' && sudo bash /tmp/koreops-i.sh
Windows : powershell -NoProfile -ExecutionPolicy Bypass -Command "...iex((New-Object Net.WebClient).DownloadString('https://<平台>/sjxy-console/agent/api/agent/i/<token>'))"
```

页面只保留一个"复制"按钮和 Linux/Windows 切换；去掉 http/https/CA 三选一（已在第一批删除）。`bootstrapUrl` 可作"下载安装脚本"链接。

### 3.3 待处理页（原"等待上线"）改语义

`GET /pending` 不变，但里面只会剩自动绑定没做成的：预绑定的资产已被别的 Agent 占用、自动建档失败、或现场关了 `agent.enroll.auto-create`。`matchedHosts` 仍返回（按 IP / 主机名找到的候选），只作人工绑定时的参考。页面标题改"待处理 Agent"，正常纳管路径不再需要打开它。可加提示："大多数 Agent 会自动绑定；此处仅列需人工判断的。"

### 3.4 补丁：统一扫描按钮

`POST /sjxy-console/secops/api/secops/patch/scan` body `{ "hostIds": [...] }` → `{ "windowsRunId", "linuxRunIds": [...], "windowsHosts": n, "linuxHosts": n }`

主机列表/漏洞页只留一个"扫描"，Linux/Windows 混选，不再区分入口。原 `win-patch/tasks/scan` 与 Workflow 作业入口保留兼容。

### 3.5 流程化任务："一键执行"

`POST /sjxy-console/secops/api/secops/v2/patch/task/{id}/run` → 返回任务实体（同 `GET /{id}`）。

- 任务详情页加"一键执行"按钮（`CREATED / PRE_CHECK_DONE / *_FAILED / RESTART_DONE` 状态下可用）。点后轮询 `GET /{id}`。
- 自动推进：预检查 → 安装/回滚 → （重启）→ 校验（校验脚本为空自动跳过）→ `COMPLETED`。
- **唯一的人工停点是重启**：平台判定需要重启时，任务停在 `INSTALL_DONE / ROLLBACK_DONE` 且 `restartConfirmed !== true`。前端此时按 `GET /{id}/restart/options` 弹确认框（原因/涉及包已给）：
  - 用户选重启 → `POST /{id}/restart/confirm {confirm:true, confirmText:'确认重启'}`，一键模式下确认即执行，**不用再点 `restart/execute`**，重启回调后自动进校验并触发漏洞重扫；
  - 用户选不重启 → `POST /{id}/restart/confirm {confirm:false}`，直接进校验。
- 平台判定不需重启（`restartType=none`）的批次不弹窗，一路跑到 `COMPLETED`。
- 失败停在对应 `*_FAILED`，修好后再点"一键执行"从该步接着跑。
- 向导模式（逐步点）完全保留，未点过"一键执行"的任务行为不变。

### 3.6 单机重启

`POST /api/secops/v2/patch/reboot-host` 不变；返回 `message` 里多了"已自动触发补丁重扫"，页面不用再提示用户手动扫描。

## 4. 不变

`POST /unbind {hostId}`；Windows / Linux 主机的安装、回滚、采集入口与参数；主机列表、任务详情的其余字段；向导模式各步接口。
