> 适用范围：根据 docs/jiesuan-sync-frontend-api-changes.md 中列出的前端相关接口变更，结合当前系统实际菜单、路由和页面入口，整理页面级测试用例。
>
> 生成时间：2026-06-22

---

## 1. 页面映射

| 菜单路径 | 路由 | 当前页面/交互 | 对应变更 |
|---|---|---|---|
| 自动化管理 > 运维工具箱 > 流程编排 | /jao/schedule | 流程列表、执行流程、流程实例列表、流程实例详情 | #1、#7 |
| 自动化管理 > 运行记录 > 运行记录 | /run-records/logs | 统一运行记录列表、运行结果弹窗、原始输出、Output 实时日志 | #4、#5、#6 |
| 自动化管理 > 工作台 | /auto-workbench/overview | 最近运行记录、流程实例、共用运行结果弹窗 | #4、#5、#6 |
| 自动化管理 > 命令执行 > 命令与运维工具 | /cmd/list、/cmd/list?tab=job | 命令列表、命令运维工具、执行命令弹窗、共用运行结果弹窗 | 共用结果视图回归关注 |
| 自动化管理 > 命令执行 > 控制台 | /cmd/console | 控制台执行命令、WebSocket 日志查看 | WebSocket 稳定性烟测 |

说明：

- 当前菜单页中，没有发现直接调用 POST /api/jao/run/command 的显式页面入口；现有命令执行主路径走的是统一 POST /api/jao/run。
- 当前菜单页中，没有发现直接使用 GET /api/jao/jobs/{runId}/running-hosts 的独立页面入口。
- 因此，本次页面级必测重点落在“流程编排”和“共用运行结果弹窗”两条用户链路上。

## 2. 页面级必测用例

## P0 用例

### TC-P0-01 流程执行时可覆盖运行参数

- 菜单路径：自动化管理 > 运维工具箱 > 流程编排
- 路由：/jao/schedule
- 关联变更：#1、#7
- 前置条件：
  1. 准备一个带全局参数的流程模板，至少包含 env、version 两个参数。
  2. 流程脚本或任务输出中可直接看到参数取值。
- 测试步骤：
  1. 进入流程编排页面，选中目标流程。
  2. 点击“执行流程”。
  3. 在“运行参数”区域，将 env、version 的默认值改为新值，例如 prod、2.0.0。
  4. 提交执行。
  5. 打开最新流程实例或对应运行结果，查看脚本输出。
- 预期结果：
  1. 执行成功创建流程实例，无参数校验异常。
  2. 后端实际执行时拿到的是本次输入的新参数，而不是模板原默认值。
  3. 运行结果、脚本输出、主机输出中能看到覆盖后的参数值。

### TC-P0-02 流程无参数改动时保持兼容

- 菜单路径：自动化管理 > 运维工具箱 > 流程编排
- 路由：/jao/schedule
- 关联变更：#1、#7
- 前置条件：准备一个已有全局参数默认值的流程模板。
- 测试步骤：
  1. 进入流程编排页面。
  2. 直接点击“执行流程”，不修改任何运行参数。
  3. 查看新生成的流程实例和执行输出。
- 预期结果：
  1. 执行链路与变更前一致，可正常运行。
  2. 脚本使用模板默认参数执行。
  3. 前端不因为 params 字段为可选而报错或拦截执行。

### TC-P0-03 运行时参数覆盖不应污染流程模板

- 菜单路径：自动化管理 > 运维工具箱 > 流程编排
- 路由：/jao/schedule
- 关联变更：#1、#7
- 前置条件：同 TC-P0-01。
- 测试步骤：
  1. 按 TC-P0-01 执行一次流程，并将参数值改成临时值。
  2. 执行完成后关闭执行界面。
  3. 重新进入该流程的“编辑”或再次打开“执行流程”。
  4. 检查流程模板中的全局参数默认值。
- 预期结果：
  1. 本次执行只影响实例，不应永久改写模板定义。
  2. 流程模板再次打开时，仍显示原始默认值，除非用户明确保存模板编辑。

### TC-P0-04 流程执行后实例列表应正常刷新与展示

- 菜单路径：自动化管理 > 运维工具箱 > 流程编排
- 路由：/jao/schedule
- 关联变更：#1、#7
- 前置条件：准备一个可成功执行的流程模板。
- 测试步骤：
  1. 进入流程编排页面并执行流程。
  2. 观察右侧实例区域或实例列表。
  3. 打开新实例详情。
- 预期结果：
  1. 新实例应出现在当前流程实例列表中。
  2. 实例状态能从待执行/运行中进入完成态。
  3. 实例详情可正常打开，不受新增 params 字段影响。

### TC-P0-05 运行结果弹窗可查看已完成任务的历史日志

- 菜单路径：自动化管理 > 运行记录 > 运行记录
- 路由：/run-records/logs
- 关联变更：#6
- 前置条件：
  1. 准备一个已完成的脚本/流程运行记录。
  2. 该记录应存在可查看的日志输出。
- 测试步骤：
  1. 进入运行记录页面。
  2. 打开一条已完成记录的运行结果弹窗。
  3. 切换到 Output 或原始输出相关页签。
  4. 关闭弹窗后再次打开同一条记录，重复查看。
- 预期结果：
  1. 已完成记录仍能读取到日志内容，不出现“空白日志”或仅连接失败。
  2. Output 页签、原始输出下载、原始文本展示保持可用。
  3. 二次打开时仍能读到历史日志，不依赖实时 ATA 日志仍存活。

### TC-P0-06 step_ 聚合结果可在共用运行结果弹窗中正常展示

- 菜单路径：自动化管理 > 运行记录 > 运行记录
- 路由：/run-records/logs
- 关联变更：#4、#5、#6
- 前置条件：
  1. 联调环境中准备一个多任务流程步骤，后端可提供 step_{stepId} 形式的聚合运行 ID。
  2. 前端需能通过现有入口把该 step_{stepId} 传入共用运行结果弹窗。
- 测试步骤：
  1. 打开对应聚合步骤的运行结果弹窗。
  2. 依次检查“概要”“按主机查看”“按列表查看”“原始输出”“Output”页签。
  3. 观察批次名称和状态汇总。
- 预期结果：
  1. 弹窗能正常打开，不因 runId 为 step_ 前缀而报错。
  2. 多任务步骤下应按“任务1 / 任务2 ...”显示批次或分组。
  3. 原始输出下载可成功返回拼接文本。
  4. Output 实时/历史日志可按 batchId 自然分组。

### TC-P0-07 聚合步骤视图下不应误触发按 runId 重跑

- 菜单路径：自动化管理 > 运行记录 > 运行记录
- 路由：/run-records/logs
- 关联变更：#4、#6
- 前置条件：联调环境中可构造 step_{stepId} 聚合视图或对应列表数据。
- 测试步骤：
  1. 进入运行记录页面，定位到聚合步骤视图对应数据。
  2. 检查该记录的“重新启动/重新执行”入口状态。
  3. 如仍可点击，尝试点击一次。
- 预期结果：
  1. 聚合步骤视图下不应把 step_ 运行 ID 当成真实单作业 runId 进行重跑。
  2. 最佳表现为按钮隐藏；若因联调数据形态仍能点到，前端也应给出明确提示并阻止提交。

## P1 用例

### TC-P1-01 工作台中的运行结果弹窗与运行记录页表现一致

- 菜单路径：自动化管理 > 工作台
- 路由：/auto-workbench/overview
- 关联变更：#4、#5、#6
- 前置条件：工作台“今日运行记录”等区域能看到可打开结果的记录。
- 测试步骤：
  1. 在工作台打开一条运行结果。
  2. 检查概要、原始输出、Output 等展示。
  3. 对比同一 runId 在“运行记录”页中的展示效果。
- 预期结果：
  1. 两个入口打开的是同一套结果视图，展示结果一致。
  2. 已完成记录同样能读取历史日志。

### TC-P1-02 命令执行模块的共用结果弹窗回归正常

- 菜单路径：自动化管理 > 命令执行 > 命令与运维工具
- 路由：/cmd/list、/cmd/list?tab=job
- 关联变更：共用结果视图回归关注
- 前置条件：可从“命令列表”直接执行命令，或从“命令运维工具”执行命令运维工具。
- 测试步骤：
  1. 在命令列表选择一条命令并执行。
  2. 或在命令运维工具页执行一条命令运维工具。
  3. 打开执行后的结果弹窗。
- 预期结果：
  1. 结果弹窗仍可正常打开。
  2. 未受本次 step_、日志读取逻辑变更影响。
  3. 已完成后重新查看时，日志内容仍可正常读取。

### TC-P1-03 控制台页面的 WebSocket 日志链路做烟测

- 菜单路径：自动化管理 > 命令执行 > 控制台
- 路由：/cmd/console
- 关联变更：#6 的日志读取稳定性回归关注
- 前置条件：准备一个执行时间较短且有明确输出的控制台命令。
- 测试步骤：
  1. 在控制台页面选择主机并执行命令。
  2. 观察日志窗口是否能实时输出。
  3. 执行完成后确认日志窗口能完整看到最终内容。
- 预期结果：
  1. WebSocket 能正常连接并输出日志。
  2. 执行完成后日志不应异常截断或立即空白。
  3. 页面不出现前端异常报错。

## 3. 非页面直连项

以下变更建议放入接口联调或补充测试，不纳入当前菜单页必测清单：

### 3.1 POST /api/jao/run/command 大批主机异步

- 当前原因：现有可见菜单页中，主命令执行入口走的是 POST /api/jao/run 或 /jao/api/jao/console-log/run，没有发现当前页面直接调用 POST /api/jao/run/command 的稳定入口。
- 建议测试方式：
  1. API 联调测试 hosts 数量 > 100 时返回 RUNNING。
  2. 校验前端若后续接入该接口，需按 check-result + result 两段式轮询。

### 3.2 GET /api/jao/jobs/{runId}/running-hosts 行为优化

- 当前原因：当前菜单页中未发现独立页面直接依赖该接口展示历史运行主机。
- 建议测试方式：
  1. 接口联调时分别验证 RUNNING、PAUSED、COMPLETED 三类状态返回。
  2. 已结束作业如需展示历史主机，应改看 runlogs/{runId}/result。

### 3.3 REST 类作业 curl 支持 ${params}

- 当前原因：属于作业配置约定变化，不是独立页面行为。
- 建议测试方式：
  1. 准备一条 REST 运维工具，在 curl 模板中使用 ${params}。
  2. 从相关执行入口带参执行后，核对实际请求体/日志中的参数替换结果。

## 4. 推荐执行顺序

1. 先做流程编排 P0 用例，确认 params 覆盖链路正确。
2. 再做运行记录 P0 用例，确认结果弹窗、原始输出、Output 日志兼容 step_ 与历史日志读取。
3. 然后做工作台和命令执行模块的 P1 回归，确认共用结果视图无回归。
4. 最后补接口联调项，覆盖当前菜单页没有稳定入口的 /run/command、running-hosts 和 REST ${params}。
