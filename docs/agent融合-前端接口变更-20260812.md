# Agent 融合 · 前端接口变更交接单（2026-08-12）

> 面向前端开发。本单只写**本次新增与变更**的部分；未提及的接口（bind / bind-gateway / unbind /
> pending / enrollment-token 的基本用法）一律不变，完整参考见 `docs/agent融合-前端接口文档.md`。
>
> **兼容性：本次为纯增量，没有删字段、没有改字段含义、没有改路径。** 前端不动代码也不会坏，
> 只是拿不到新增能力；下面第 5 节列了要改哪些页面。
>
> 网关前缀与现有 CMDB 接口一致（`/cmdb/api/cmdb/...`，自动带 `Authorization`、`Tenant-Id`），
> 下文路径均写后端路径。

---

## 1. 变更总览

| 类型 | 内容 |
|---|---|
| 新增接口 | `POST /api/cmdb/agent/sync-ip`、`GET /api/cmdb/agent/route-mismatch` |
| 字段新增 | `host-info` 增 6 个字段；`enrollment-token` 增 `remainingUses` / `targetOs` / 4 个安装命令变体 |
| 行为变更 | 下发前新增路由一致性闸门，错位目标会被**直接阻断**并返回可读原因 |
| 请求参数新增 | `POST /api/cmdb/agent/enrollment-token` 增可选入参 `targetOs` |

变更的起因：Agent 通道的命令投递依据是绑定时写进主机 Ansible 参数的 `client_id`，而界面上展示和
运维用来核对的是 CMDB 资产的 IP。DHCP 续租换地址后两者分叉，**界面上勾的是 A、命令实际打到 B，
且事后从任务详情看不出来**。所以后端做了两件事：把两个地址都吐给前端，以及在下发前把不一致的目标拦下。

---

## 2. 新增接口

### 2.1 同步资产主 IP

`POST /api/cmdb/agent/sync-ip`

把 CMDB 资产的主 IP 改写为该 Agent 当前实际上报的 IP，用于消除 §3.1 里的 `ipMismatch`。

请求体：

```json
{ "hostId": "ci-1001", "clientId": "desk-95-001", "confirm": true }
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `hostId` | 是 | 资产 id |
| `clientId` | 否 | 传了会校验与该资产的绑定记录一致，不一致直接拒绝——防止用户在列表里选错行 |
| `confirm` | 是，且必须为 `true` | 见下方说明 |

成功返回 HTTP 200，body 为字符串 `"ok"`。

**`confirm` 不是走过场，前端必须弹确认框**，并在框里写清具体的变更（`10.20.0.33` → `10.20.0.51`），
不要做成一键静默同步。原因：CMDB 主 IP 被工单、审计、防火墙策略和 SSH 纳管通道引用，
短租约 DHCP 环境下静默改写会让资产库反复抖动，影响面远超 Agent 模块。这也是后端**默认不自动同步**的原因。

其它行为：

- 幂等。两个 IP 已经一致时返回成功且不写审计。
- 目标地址是平台自身时拒绝写入（`PLATFORM_SELF_BIND`）。
- 成功后前端应重新拉一次 `host-info`，`ipMismatch` 应变为 `false`。

错误码（400，body 形态见 §4）：

| errorCode | 场景 |
|---|---|
| `HOST_NOT_FOUND` | 资产不存在，或该资产没有有效的 Agent 绑定 |
| `CLIENT_ALREADY_BOUND` | 传入的 `clientId` 与该资产的绑定记录不一致 |
| `AGENT_OFFLINE` | 该 Agent 从未上报过 IP，没有可同步的值 |
| `PLATFORM_SELF_BIND` | 待写入的地址是平台自身 |

### 2.2 存量路由错位清查

`GET /api/cmdb/agent/route-mismatch`

无入参，只读，把当前租户下所有已绑定资产跑一遍全量比对。适合做一个「Agent 接入体检」入口，
在批量下发之前先让运维看清有多少台、哪些台。

返回数组：

```json
[
  {
    "kind": "IP_MISMATCH",
    "ciId": "ci-1001",
    "hostname": "PC-FIN-01",
    "cmdbIp": "10.20.0.33",
    "effectiveIp": "10.20.0.51",
    "clientId": "desk-95-001",
    "agentMode": "local",
    "lastSeenAt": "2026-08-12 09:50:12.0",
    "message": "CMDB 记录 IP 为 10.20.0.33，但其绑定的 Agent(clientId=desk-95-001) 实际所在地址为 10.20.0.51。命令按 client_id 投递，会打到后者上。"
  }
]
```

- `effectiveIp` 是**实际会被执行的地址**：`local` 模式为 Agent 自报 IP，`gateway` 模式为代管的目标 IP。
- `message` 是给运维看的完整判断依据，前端**原样展示**，不要自己拼文案。
- 每行提供「同步资产 IP」按钮（调 §2.1，`hostId` 取 `ciId`）和「去资产详情修改」两个出口。
- 空数组表示没有错位。
- `lastSeenAt` 是 `Timestamp.toString()` 的原始串（带 `.0` 毫秒尾巴），前端展示前自行截断格式化。

**当前实现只会返回 `kind == "IP_MISMATCH"`。** 另外三种错位（`CLIENT_ID_STALE` /
`BINDING_MISSING` / `PLATFORM_SELF`）目前只在实际下发时由闸门判定并阻断（见 §3.3），
本接口扫不出来。前端按数组里实际的 `kind` 渲染即可，不必为另外三种预留清查页逻辑。

## 3. 已有接口的字段变更

### 3.1 `GET /api/cmdb/agent/host-info?hostIds=id1,id2`

路径、入参、返回结构都不变，**每个元素新增 6 个字段**：

| 新增字段 | 类型 | 说明 |
|---|---|---|
| `os` | string | Agent 上报的原始 os 串，如 `"Windows 10"` / `"Linux 4.19.90"` |
| `agentPlatform` | string | 归一后的平台：`windows` / `linux` / `unknown`。要按系统区分按钮时用这个，别去解析 `os` |
| `cmdbIp` | string | CMDB 资产档案里的主 IP（**SSH 主机也会返回**，其余 agent 字段仍为 null） |
| `lastReportedIp` | string | Agent 最近一次上报的 IP，DHCP 下会变 |
| `lastReportedAt` | string | 上报时间，`yyyy-MM-dd HH:mm:ss` |
| `ipMismatch` | boolean | 两者是否已分叉 |

```json
{
  "hostId": "ci-1001",
  "connectionType": "koreops_agent",
  "agentStatus": "online",
  "agentClientId": "desk-95-001",
  "agentVersion": "1.0.3",
  "capabilities": "scan,patch,rollback,exec,put,fetch",
  "agentMode": "local",
  "targetIp": null,
  "lastSeenAt": "2026-08-12 09:50:12",
  "os": "Windows 10",
  "agentPlatform": "windows",
  "cmdbIp": "10.20.0.33",
  "lastReportedIp": "10.20.0.51",
  "lastReportedAt": "2026-08-12 09:50:12",
  "ipMismatch": true
}
```

`ipMismatch == true` 时前端要显式提示，**不能只显示 `cmdbIp`**——那是配置态的值，
实际机器在 `lastReportedIp` 上，界面上那个 IP 既不能用来 SSH 也不能用来配防火墙。
这类主机下发时会被闸门直接拦下，所以提示要引导用户去同步资产 IP（§2.1）或修正资产记录，
而不是让他反复重试下发。

### 3.2 `POST /api/cmdb/agent/enrollment-token`

请求体新增可选字段 `targetOs`，取值 `linux`（默认）/ `ubuntu` / `debian` / `windows`，
只影响返回里 `installCommand` 选哪个变体：

```json
{ "ttlMinutes": 60, "maxUses": 1, "remark": "财务部台式机", "targetOs": "windows" }
```

返回新增字段：

| 新增字段 | 说明 |
|---|---|
| `remainingUses` | 剩余可用次数。status 非 `active` 时恒为 0 |
| `targetOs` | 回显请求值，便于确认拿到的是哪个版本 |
| `installCommand` | 按 `targetOs` 选好的那一条，**前端直接展示这个**即可 |
| `installCommandLinuxHttps` | 麒麟/RHEL 系 |
| `installCommandLinuxHttp` | Ubuntu/Debian 用 |
| `installCommandLinuxCa` | 先取平台 CA 再严格校验，正式环境推荐 |
| `installCommandWindows` | PowerShell 版 |

前端展示 `installCommand`（一键复制）、`expiresAt`、`remainingUses`。

`remainingUses` 为 0，或 `status` 是 `exhausted` / `expired` 时，「等待上线」页要直接提示
「这张凭证已不可用，请回上一步重新生成」，不要让用户对着空列表继续等——**安装失败也计入消耗**，
等下去不会有结果。这也是加 `remainingUses` 的目的。

命令形态有两点和早期版本不同，**请不要在前端自行改回去**：

1. **先落盘再执行，不用管道。** `curl ... | sudo sh` 在 curl 失败时 `sh` 读到空输入正常退出，
   整条命令退出码是 0，运维会把失败当成安装成功。
2. **带 `-k`。** 平台多为自签证书，端点信任库里没有它，不加 `-k` 第一步就 `curl(60)`。
   要做证书校验请用 `installCommandLinuxCa` 那条，而不是把 `-k` 去掉。

### 3.3 下发行为变更：路由闸门

任务下发接口本身**没有变**（前端不新增调用），但后端在目标解析处加了一道一致性校验。
存在错位的目标会下发失败，错误信息以 `[AgentRouteMismatch]` 开头，形如：

```
[AgentRouteMismatch] 为避免命令下发到错误主机，本次下发已阻断。共 2 台目标存在资产与执行落点不一致：
- [IP_MISMATCH] ciId=ci-1001 (PC-FIN-01) CMDB记录IP=10.20.0.33 实际执行地址=10.20.0.51：CMDB 记录 IP 为 ...
- [PLATFORM_SELF] ciId=ci-2002 (oplus-node) CMDB记录IP=192.168.1.219 实际执行地址=192.168.1.219：目标 ... 是平台自身地址 ...
请先核对资产绑定关系（控制台可查 GET /api/cmdb/agent/route-mismatch）后重试。
```

这段是多行文本，**前端要保留换行原样展示**（不要塞进单行 toast 截断），它是运维判断
「该改资产还是该重新绑定」的唯一依据。四种 `kind` 的含义与处置：

| kind | 含义 | 引导用户做什么 |
|---|---|---|
| `IP_MISMATCH` | CMDB 记录 IP 与 Agent 实际所在地址不同 | 同步资产 IP（§2.1）或修正资产记录 |
| `CLIENT_ID_STALE` | 主机连接参数里的 `client_id` 与绑定记录不一致（重新绑定后未刷新） | 重新绑定一次 |
| `BINDING_MISSING` | 连接参数指向某个 Agent，但库里已无有效绑定 | 重新绑定，或清理该资产的连接参数 |
| `PLATFORM_SELF` | 目标是平台自身 | 不要下发。平台节点不作为被纳管对象 |

超过 5 台时消息里只列前 5 台，其余提示「见后端日志」，前端不用做分页。

## 4. 错误响应的两种形态

`/api/cmdb/agent/**` 下的 400 有两种 body，前端要都能处理：

**形态一：业务错误码**（bind / bind-gateway / sync-ip 抛出的业务异常）

```json
{ "errorCode": "CLIENT_ALREADY_BOUND", "message": "……" }
```

**形态二：参数校验**（如 `sync-ip` 没传 `confirm` 或 `hostId` 为空），走平台统一的 Problem 格式，
**没有 `errorCode`**：

```json
{ "title": "Bad Request", "status": 400, "detail": "同步 CMDB 主 IP 需要显式确认(confirm=true)。……" }
```

建议前端统一取 `errorCode` 做文案映射，取不到时回落展示 `message ?? detail`。

## 5. 前端改造清单

按页面归拢，方便排任务：

| 页面 | 要做的事 | 依赖 |
|---|---|---|
| 主机列表 / 主机详情 | `ipMismatch==true` 的行加警示标记，同时展示 `cmdbIp` 与 `lastReportedIp`；提供「同步资产 IP」入口 | §3.1、§2.1 |
| 主机列表 | 按 `agentPlatform` 区分 Windows / Linux 主机的可用操作（不要解析 `os` 字符串） | §3.1 |
| 纳管向导 · 生成凭证 | 增加「目标系统」选择，作为 `targetOs` 传入 | §3.2 |
| 纳管向导 · 等待上线 | 展示 `remainingUses`；为 0 或 status 非 active 时中止轮询并提示重新生成 | §3.2 |
| 任务下发结果 | 识别 `[AgentRouteMismatch]` 开头的失败信息，多行原样展示，并给出跳转「接入体检」的入口 | §3.3 |
| 新增：Agent 接入体检 | 列表化展示 `route-mismatch` 结果，每行给「同步资产 IP」和「去资产详情」两个出口 | §2.2 |

## 6. 权限

后端做的是服务端角色校验，不是靠前端隐藏按钮；无权限调用返回 403。

| 接口 | 所需角色 |
|---|---|
| `sync-ip`（以及既有的 enrollment-token / bind / bind-gateway / unbind） | ADMIN / PRIVUSER / DEVELOPER / FREE |
| `route-mismatch`（以及既有的 pending / host-info） | 登录态（ROLE_USER） |

前端仍应按角色控制入口可见性，但授权以后端为准。
