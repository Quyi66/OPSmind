网关前缀：

- 管理面：与现有 CMDB 接口一致，前端实际请求 `{网关}/cmdb/api/cmdb/agent/...`，自动带 `Authorization`、`Tenant-Id`。补丁面为 `{网关}/secops/api/secops/...`。
- Agent / Relay 面：`{server}/agent/api/agent/...`（`server` 形如 `https://192.168.1.150/sjxy-console`），Shiro 匿名放行，由控制器按 token 头自校验。

扫描 / 安装 / 回滚 / 连通性 / 采集：**没有任何 Agent 专用接口**，前端继续调现有任务接口，后端在收口点自动按绑定表选通道。

已下线、请求会 404/405 的旧接口：`POST/GET/DELETE /api/cmdb/agent/enrollment-token[/{id}]`、`POST /bind-gateway`（用 `bind` + `mode=gateway`）、`POST /sync-ip`、`GET /route-mismatch`。

## 1. 通用约定

### 1.1 错误响应

管理面 400：

```json
{ "errorCode": "HOST_ALREADY_BOUND", "message": "该资产已绑定 Agent，请先解绑" }
```

参数校验失败走平台统一 Problem 格式（无 `errorCode`），前端取 `errorCode ?? detail`：

```json
{ "title": "Bad Request", "status": 400, "detail": "clientId 和 hostId/newHost 不能同时为空" }
```

Agent 面 401：

```json
{ "ok": false, "errorCode": "NEED_REENROLL", "message": "…", "retryable": false }
```

Relay 面：HTTP 恒 200，错误放在 body 的 `errorCode`（见 §5）。

### 1.2 错误码（共 11 个）

| errorCode | 面 | 含义 | 前端文案建议 |
|---|---|---|---|
| `AGENT_OFFLINE` | 管理 / 任务下发 / Relay | Agent 未注册或 90s 内无心跳 | Agent 离线，暂不可执行 |
| `AGENT_AUTH_FAILED` | Agent / Relay | 缺 token 或 relay token 不匹配 | — |
| `NEED_REENROLL` | Agent | clientToken 已作废（解绑 / 吊销），须用新凭证重新纳管 | — |
| `ENROLL_TOKEN_INVALID` | Agent | 纳管凭证无效；响应体附 `reason: expired \| exhausted \| revoked \| identity_mismatch \| unknown` | — |
| `DISPATCH_TIMEOUT` | Relay | 单条指令超过 `agent.dispatch.timeout-sec` 未回结果 | 下发/执行超时 |
| `COMMAND_FAILED` | Relay | 指令送达但执行异常 | 主机命令执行失败 |
| `RELAY_UNAVAILABLE` | Relay | 通道内部中断 | 通道不可达 |
| `CLIENT_ALREADY_BOUND` | 管理 | 该 Agent 已绑定其他资产 | 该 Agent 已绑定其他资产 |
| `HOST_ALREADY_BOUND` | 管理 | 目标资产已绑定 Agent | 该资产已绑定 Agent，请先解绑 |
| `HOST_NOT_FOUND` | 管理 | 资产不存在 / 不属于当前租户 / 无有效绑定 | 资产不存在 |
| `PLATFORM_SELF` | 管理 / 任务下发 | 目标或 Agent 所在机是平台自身 | 平台节点不能作为被纳管对象 |

任务下发被收口点拒绝时（目标含平台自身地址），任务接口返回的失败信息以 `[AgentRoute]` 开头、多行、逐台列出：

```
[AgentRoute] 本次下发已阻断，1 台目标不可执行：
- [PLATFORM_SELF] ciId=ci-2002 (oplus-node) 目标 192.168.1.150 是平台自身地址
```

前端保留换行原样展示，不要截断。Agent 离线**不**整批阻断：与 SSH 主机不可达同一口径，该主机照常进入运行，在运行记录里以 `AGENT_OFFLINE` 单独失败，其余主机不受影响。所以前端仍要按 `host-info.agentStatus` 预先禁按钮。

### 1.3 时间格式

管理面所有时间字段 `yyyy-MM-dd HH:mm:ss`（GMT+8）。

## 2. 管理面

### 2.1 生成纳管凭证

`POST /api/cmdb/agent/enroll-tokens`

请求（均可选）：

```json
{ "targetOs": "windows", "ttlMinutes": 1440, "maxUses": 0, "remark": "财务部台式机", "hostId": null, "node": null }
```

| 字段 | 默认 | 说明 |
|---|---|---|
| `targetOs` | `linux` | `linux` / `windows`，决定引导脚本形态；传了 `hostId` 时按资产类型自动取 |
| `ttlMinutes` | 1440（24h） | 有效期 |
| `maxUses` | 0 | 0 = 有效期内不限次；传 1 即一次性；传了 `hostId` 强制 1 |
| `remark` | — | 备注 |
| `hostId` | — | **预绑定资产**（从资产行"生成本机安装命令"进来）。凭此凭证注册的 Agent 直接绑到该资产，不进待处理列表。资产不存在 → 400 `HOST_NOT_FOUND`，已绑 Agent → `HOST_ALREADY_BOUND`，平台自身 → `PLATFORM_SELF` |
| `node` | — | 仅通用凭证、仅多节点形态：装出来的 Agent 连哪个接入节点（与执行机实例组同名）。预绑定凭证忽略此字段，按资产的 `instance_group` 取。单机形态不传 |

响应：

```json
{
  "id": "tok-abc",
  "token": "H8s...Uk",
  "targetOs": "windows",
  "hostId": null,
  "clientId": "kops-60591a2c554a",
  "server": "https://192.168.1.150/sjxy-console",
  "status": "active",
  "maxUses": 0,
  "usedCount": 0,
  "remainingUses": null,
  "expiresAt": "2026-09-11 11:40:00",
  "bootstrapUrl": "https://192.168.1.150/sjxy-console/agent/api/agent/i/H8s...Uk",
  "installCommand": "powershell -NoProfile -ExecutionPolicy Bypass -Command \"[Net.ServicePointManager]::ServerCertificateValidationCallback={$true};[Net.ServicePointManager]::SecurityProtocol='Tls12';iex((New-Object Net.WebClient).DownloadString('https://192.168.1.150/sjxy-console/agent/api/agent/i/H8s...Uk'))\""
}
```

- `token` 明文仅本次返回。
- `remainingUses`：`maxUses=0` 时为 `null`（不限），否则 `maxUses - usedCount`。
- `installCommand` **一行**，在目标机以 root / 管理员执行，前端只需一个"复制"按钮。Linux：`curl -fsSLk -o /tmp/koreops-i.sh '<bootstrapUrl>' && sudo bash /tmp/koreops-i.sh`；Windows 如上，cmd 或 PowerShell 都能贴。命令本身只含地址，server / token / CA 引导 / http 回退全在平台渲染的引导脚本里（§4.0）。
- `clientId`：**平台签发的 Agent 身份**（`kops-` + 12 位十六进制），单次凭证（`maxUses=1`，含所有预绑定凭证）才有，多次凭证为 `null`。它已写进引导脚本，前端不用往命令里拼；资产行签发时可在页面上显示"Agent 身份：kops-…"，装好后 `host-info.agentClientId` 就是它。平台认这个身份不认 IP。
- `server`：这张凭证装出的 Agent 的接入基址。多节点形态下为所属区域执行机的地址；单机为平台地址。已拼进 `bootstrapUrl` / `installCommand`，前端不用改拼接。
- `bootstrapUrl` 可作"下载安装脚本"链接。

**页面**：凭证页只保留 Linux / Windows 切换（切换即重新调本接口，或一次生成两张）和一个"复制"按钮；不区分 http / https / CA。通用凭证（不传 `hostId`）给新机器；要对到已有资产只走资产行"生成本机安装命令"（传 `hostId`）。

### 2.2 平台推装 Agent（已录资产，人不登目标机）

`POST /api/cmdb/agent/install`　请求 `{ "hostIds": ["h1", "h2"] }`

```json
{ "runId": "run-xxx", "submitted": ["h1"], "skipped": { "h2": "已由 Agent 纳管（cid…），如需重装先解绑" } }
```

- 平台用资产已有 SSH / WinRM 凭据登上去装 Agent，Agent 注册即绑到该资产。Linux / Windows 混选合成一个 run。
- `skipped` 逐台给原因，不算错误：资产不存在 / 不属当前租户、平台自身地址、已被 Agent 纳管。400 `{message}` 仅在 `hostIds` 为空时。
- 结果看两处：轮询 `GET /host-info?hostIds=`，`agentStatus` 变 `online` 即成功（一般 1～3 分钟）；`runId` 可链到作业记录看逐台失败原因（凭据错 / 不可达 / 安装失败分列）。
- `POST /api/cmdb/agent/install/callback` 是 workflow 回调，前端不用管。

**页面**：主机列表按钮"安装 Agent"，只对 `host-info.connectionType !== 'koreops_agent'` 的行显示。

### 2.3 撤销凭证

`DELETE /api/cmdb/agent/enroll-tokens/{id}` → `200 "ok"`。已用该凭证注册的 Agent 不受影响（它们持有的是 clientToken）。

### 2.4 待处理 Agent

`GET /api/cmdb/agent/pending?tokenId=tok-abc`

`tokenId` 可选；传了则响应带 `token` 段。建议轮询间隔 3～5s。

注册时平台先自动绑定（预绑定凭证 → 直接绑该资产；通用凭证 → 自动建档并绑）。平台**不按 IP 匹配已有资产**。**列表里只剩**：预绑定的资产已被别的 Agent 占用（先解绑再绑）、自动建档失败、或现场关了 `agent.enroll.auto-create`。正常纳管不需要打开此页。

```json
{
  "token": {
    "id": "tok-abc",
    "status": "active",
    "remainingUses": null,
    "expiresAt": "2026-09-11 11:40:00"
  },
  "agents": [
    {
      "clientId": "desk-189a1dcdb79e",
      "hostname": "WIN-IBP0LHHQ0CD",
      "ip": "192.168.1.93",
      "os": "Windows 10.0.17763",
      "agentPlatform": "windows",
      "agentVersion": "2.6.1",
      "capabilities": "scan,patch,rollback,exec,put,fetch",
      "agentStatus": "online",
      "registeredAt": "2026-09-10 11:35:02",
      "lastSeenAt": "2026-09-10 11:39:50",
      "matchedHosts": [
        { "hostId": "ci-3001", "hostname": "WIN-IBP0LHHQ0CD", "ip": "192.168.1.93", "ciType": "windows", "matchedBy": "ip,hostname" }
      ]
    }
  ]
}
```

- `agents` = 当前租户下已注册、`hostId` 为空的 Agent（含所绑资产已被删除的）。
- `matchedHosts`：按 `ip` 或 `hostname` 命中的已有资产，**只是候选**，后端不做任何自动绑定。0 条 → 前端默认选"新建资产"；≥1 条 → 让管理员挑，或仍可选新建。
- `token.status` 非 `active`、或 `remainingUses === 0` 时，前端停止轮询并提示"凭证已不可用，请重新生成"。
- 按平台区分图标 / 按钮用 `agentPlatform`，不要解析 `os` 字串。

**页面**：标题"待处理 Agent"，可加提示"大多数 Agent 会自动绑定；此处仅列需人工判断的"。

### 2.5 绑定（建档 + 绑定一步完成）

`POST /api/cmdb/agent/bind`

三种用法，`hostId` 与 `newHost` **二选一**：

**a. 本机模式，绑到已有资产**

```json
{ "clientId": "desk-189a1dcdb79e", "hostId": "ci-3001" }
```

**b. 本机模式，新建资产**

```json
{ "clientId": "desk-189a1dcdb79e", "newHost": {} }
```

`newHost` 可全空：后端用该 Agent 上报的 `hostname / ip / os` 建资产，CI 类型按 `agentPlatform` 选 `linux` / `windows`。也可显式覆盖：

```json
{ "clientId": "desk-189a1dcdb79e",
  "newHost": { "hostname": "PC-FIN-01", "ip": "192.168.1.93", "ciType": "windows", "groupIds": ["g-1"] } }
```

**c. 跳板模式（登记由该 Agent 代管的内网主机）**

```json
{ "clientId": "desk-95-001", "mode": "gateway", "targetIp": "10.0.0.5",
  "newHost": { "hostname": "db-01", "ip": "10.0.0.5", "ciType": "linux" } }
```

或 `hostId` 指向已有资产。`targetIp` 必填；一台 Agent 可 gateway 多台。

| 字段 | 必填 | 说明 |
|---|---|---|
| `clientId` | 是 | 来自 `pending.agents[].clientId`，或已绑定 Agent 的 `host-info.agentClientId`（gateway 时） |
| `hostId` | 与 `newHost` 二选一 | 已有资产 |
| `newHost` | 与 `hostId` 二选一 | `{hostname?, ip?, ciType?, osVersion?, osDistro?, groupIds?}` |
| `mode` | 否 | `local`（默认）/ `gateway` |
| `targetIp` | gateway 必填 | 内网目标地址 |

响应 200：

```json
{
  "hostId": "ci-3001",
  "clientId": "desk-189a1dcdb79e",
  "agentMode": "local",
  "targetIp": null,
  "agentStatus": "online",
  "hostCreated": true
}
```

错误：`HOST_ALREADY_BOUND` / `CLIENT_ALREADY_BOUND` / `HOST_NOT_FOUND` / `AGENT_OFFLINE`（该 clientId 未注册）/ `PLATFORM_SELF`。

**页面**：绑定成功后跳 `hostId` 详情，不再跳"新增主机"页。绑定界面把 Agent 上报的 `hostname / ip` 与所选资产的 `hostname / ip` 并排显示供核对。

### 2.6 解绑

`POST /api/cmdb/agent/unbind`　`{ "hostId": "ci-3001" }` → `200 "ok"`。

local 绑定：摘掉 `hostId`，Agent 回到待处理列表，可重新绑定；gateway 绑定：删除该行。

### 2.7 主机 Agent 信息（列表 / 详情 / 任务详情富化）

`GET /api/cmdb/agent/host-info?hostIds=id1,id2,id3`

返回数组，与入参顺序一致：

```json
[
  {
    "hostId": "ci-3001",
    "connectionType": "koreops_agent",
    "agentClientId": "desk-189a1dcdb79e",
    "agentMode": "local",
    "agentNode": null,
    "targetIp": null,
    "agentStatus": "online",
    "agentVersion": "2.6.1",
    "capabilities": "scan,patch,rollback,exec,put,fetch",
    "os": "Windows 10.0.17763",
    "agentPlatform": "windows",
    "cmdbIp": "192.168.1.93",
    "agentIp": "192.168.1.93",
    "ipMismatch": false,
    "lastSeenAt": "2026-09-10 11:39:50"
  },
  { "hostId": "ci-1002", "connectionType": "ssh", "cmdbIp": "192.168.1.94" }
]
```

| 字段 | 说明 |
|---|---|
| `connectionType` | `ssh` / `koreops_agent`（有效绑定即为后者；WinRM 主机也是 `ssh`） |
| `agentStatus` | `online` / `offline`；SSH 主机为 `null`。没有 `unknown` |
| `agentMode` / `targetIp` | `local` / `gateway`；gateway 时 `targetIp` 为代管目标 |
| `agentNode` | 所连接入节点（执行机实例组名）；`null` = 直连平台。可展示可忽略 |
| `agentPlatform` | `windows` / `linux` / `unknown`，按平台区分按钮用这个，不要解析 `os` |
| `cmdbIp` | 资产档案主 IP（SSH 主机也返回） |
| `agentIp` | local 时 Agent 最近上报 IP；gateway 时 = `targetIp`。即命令实际落点 |
| `ipMismatch` | `cmdbIp` 与 `agentIp` 都有值且不同。**仅提示**，不阻断下发，没有"同步资产 IP"操作 |
| `lastSeenAt` | 最近心跳 |

Windows 补丁主机列表（`/secops/api/secops/win/hosts`）里附带的 Agent 字段同上。

**按钮规则**：SSH 主机沿用现有逻辑；Agent 主机 `agentStatus==online` 且 `capabilities` 含对应能力（scan / patch / rollback）才可用，否则禁用并给出原因；批量选择时展示"可执行 N 台 / 不可执行 M 台 + 原因"，不静默跳过。

## 3. 补丁任务入口（前端）

### 3.1 统一扫描

`POST /api/secops/patch/scan`　`{ "hostIds": [...] }` → `{ "windowsRunId", "linuxRunIds": [...], "windowsHosts": n, "linuxHosts": n }`

主机列表 / 漏洞页只留一个"扫描"，Linux / Windows 混选，后端按 CI 类型分流。原 `win-patch/tasks/scan` 与 Workflow 作业入口保留兼容。

### 3.2 流程化任务"一键执行"

`POST /api/secops/v2/patch/task/{id}/run` → 任务实体（同 `GET /{id}`）。

- 任务详情页加"一键执行"按钮，`CREATED / PRE_CHECK_DONE / *_FAILED / RESTART_DONE` 状态下可用。点后轮询 `GET /{id}`。
- 自动推进：预检查 → 安装 / 回滚 → （重启）→ 校验（校验脚本为空自动跳过）→ `COMPLETED`。
- **唯一的人工停点是重启**：平台判定需要重启时，任务停在 `INSTALL_DONE / ROLLBACK_DONE` 且 `restartConfirmed !== true`。前端此时按 `GET /{id}/restart/options` 弹确认框（原因 / 涉及包已给）：
  - 选重启 → `POST /{id}/restart/confirm {confirm:true, confirmText:'确认重启'}`，确认即执行，**不用再点 `restart/execute`**；重启回调后自动进校验并触发漏洞重扫。
  - 选不重启 → `POST /{id}/restart/confirm {confirm:false}`，直接进校验。
- 平台判定不需重启（`restartType=none`）的批次不弹窗，一路跑到 `COMPLETED`。
- 失败停在对应 `*_FAILED`，修好后再点"一键执行"从该步接着跑。
- 向导模式（逐步点）完全保留，未点过"一键执行"的任务行为不变。

### 3.3 单机重启

`POST /api/secops/v2/patch/reboot-host` 不变；完成后自动触发该主机补丁重扫，返回 `message` 里已说明，页面不用再提示用户手动扫描。

## 4. Agent 面（客户端协议，与 agent.py 2.6.1 完全兼容）

BASE = `{server}/agent/api/agent`。JSON 一律 camelCase，头 `X-Agent-Token`。

### 4.0 引导脚本（一行安装命令背后拉的东西）

`GET {BASE}/i/{enrollmentToken}` → `200 text/plain`（`Cache-Control: no-store`）

- 凭证 `targetOs=linux`：bash 脚本，内容为 `curl -fsSLk -o /tmp/koreops-install.sh {server}/agent/install.sh && exec bash /tmp/koreops-install.sh --token … --server … [--client-id …]`。
- `targetOs=windows`：PowerShell 脚本，WebClient + TLS1.2 + 忽略自签证书，下载 `{server}/agent/wheels/win/install.ps1` 后以 `-Token -Server [-ClientId]` 执行。
- `{server}` 取凭证固化的 `server` 字段（多节点时为所属执行机接入点）。
- 只校验凭证仍 `active`，**不消耗次数**（消耗发生在随后的 register）。无效 / 过期 / 用尽 / 吊销一律 `404` 纯文本，不区分原因。
- 凭证会出现在 URL 与 nginx 访问日志里：凭证本就是短期、一次性（预绑定）或限次的，保持 `ttlMinutes` 短即可。

### 4.1 注册 / 重连

`POST {BASE}/register`，头 `X-Agent-Token: <enrollment token 或 client token>`

```json
{ "clientId": "desk-189a1dcdb79e", "hostname": "WIN-IBP0LHHQ0CD", "ip": "192.168.1.93",
  "os": "Windows 10.0.17763", "agentVersion": "2.6.1", "capabilities": "scan,patch,rollback,exec,put,fetch" }
```

| 情形 | 结果 |
|---|---|
| clientId 未见过 + 有效 enrollment token | 先校验身份：凭证带 `clientId`（单次凭证）而上报的不一致 → `ENROLL_TOKEN_INVALID [reason=identity_mismatch]`，凭证不消耗。通过后创建绑定记录并**自动绑定**（凭证带 hostId → 绑该资产；否则 `agent.enroll.auto-create` → 建档后绑；资产被占 → 留待处理），`200 {ok:true, clientToken:"…"}`；Agent 落盘 clientToken。自动绑定失败不影响注册。**不按 IP 匹配** |
| clientId 已知 + client token 匹配 | 刷新元数据与在线，`200 {ok:true}` |
| clientId 已知 + token 不匹配，但它是一张有效 enrollment token | **就地换发** 新 clientToken，`200 {ok:true, clientToken:"…"}`（"踢下线 → 重新签发 → 不登机重装"路径） |
| token 无效 | `401 {ok:false, errorCode, message, retryable:false, reason?}` |
| 上报 IP 是平台地址 | `401 errorCode=PLATFORM_SELF` |

注册与每次 poll 都会记录 Agent 所连的接入节点（`agentNode`），Agent 换节点连接时自动更新。

### 4.2 长轮询取指令（兼心跳）

`GET {BASE}/poll?clientId=…&ip=…&hostname=…`

- `ip` / `hostname` 可选；变化时刷新绑定行，供 DHCP 场景展示。
- 挂起最长 30s；有指令 `200` 返回指令体，无指令 `204`。
- `401` 同 §4.1 错误体；Agent 据 `retryable` 决定退避策略。
- 鉴权走进程内缓存（`agent.auth-cache-sec`，默认 60s），心跳只写在线表，`last_seen_at` 每 `agent.runtime.flush-ms`（默认 5 分钟）批量落库一次。

指令体：

```json
{ "cmdId": "uuid", "type": "exec", "target": null, "shell": "powershell", "cmd": "…" }
{ "cmdId": "uuid", "type": "put",   "target": "10.0.0.5", "dest": "/tmp/x", "content": "<base64>" }
{ "cmdId": "uuid", "type": "fetch", "target": null, "src": "/tmp/result.json" }
```

- `target` 空 = 本机执行；非空 = gateway 模式，Agent 用本地 `targets.json` 里的凭据经 SSH（Linux）/ WinRM（Windows）转发。
- `shell`：`sh` / `powershell` / `cmd`，由平台按该 Agent 的 `os` 判定填入。

### 4.3 回传结果

`POST {BASE}/result?clientId=…`

```json
{ "cmdId": "uuid", "rc": 0, "stdout": "…", "stderr": "…", "content": "<base64，仅 fetch>" }
```

→ 恒 `200 "ok"`（含重复 / 未知 cmdId，幂等由 Agent 侧 `cmd-history.json` 保证）。超时映射 `rc=124`。

## 5. Relay 面（executor 连接插件 → 平台 / 本机接入节点，内部）

头 `X-Relay-Token: <agent.relay.internal-token>`；配置为空时不校验（仅开发）。三个接口均**同步等待** Agent 结果，上限 `agent.dispatch.timeout-sec`（默认 120s）；插件 HTTP 超时 = 该值 + 10s。

| 路径 | 请求体 | 说明 |
|---|---|---|
| `POST /relay/exec` | `{clientId, target?, cmd, shell?}` | `shell` 缺省时平台按绑定 os 判定 |
| `POST /relay/put` | `{clientId, target?, dest, content(base64)}` | |
| `POST /relay/fetch` | `{clientId, target?, src}` | 结果在响应 `content` |

响应（HTTP 恒 200）：

```json
{ "rc": 0, "stdout": "…", "stderr": "…", "content": null, "errorCode": null, "message": null }
```

`errorCode` 非空表示通道层失败（`AGENT_OFFLINE` / `DISPATCH_TIMEOUT` / `COMMAND_FAILED` / `RELAY_UNAVAILABLE` / `AGENT_AUTH_FAILED`），此时 `rc=-1`，插件把它当该主机 UNREACHABLE，ansible 走正常失败分支。

## 6. inventory 连接参数（派生，不落库）

任务下发时，收口点 `CmdbAutomationServiceImpl` → `AgentRouteResolver` 对每台有有效绑定的主机在内存里生成：

```
ansible_connection=koreops_agent koreops_agent_client_id=desk-95-001 koreops_relay_url=https://192.168.1.150/sjxy-console/agent/api/agent
ansible_connection=koreops_agent koreops_agent_client_id=desk-95-001 koreops_relay_url=… koreops_agent_target=10.0.0.5   # gateway
```

- 绑定行有 `node` 时：作业的实例组改为该 `node`（投到 Agent 所连的执行机），`koreops_relay_url` 取 `agent.relay.node-url`（执行机本机 relay）；否则用 `agent.relay.url`（平台）。
- 硬规则：目标 / Agent 所在机 / targetIp 任一为平台地址 → `PLATFORM_SELF`，整批拒绝，错误信息格式见 §1.2。Agent 不在线只记 warn 并照常下发，由插件按 `AGENT_OFFLINE` 单台失败。
- executor 节点插件 `koreops_agent.py` 读取 `koreops_*`（过渡期兼容 `oplus_*`），relay token 从进程环境变量 `AGENT_RELAY_INTERNAL_TOKEN` 取，不进 inventory。
