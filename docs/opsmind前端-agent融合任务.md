# OpsMind 前端任务：Agent 主机原生融合

## 目标

在现有“补丁漏洞 → 补丁管理(Linux) → 主机概览”中统一展示 SSH 与 Agent 主机。用户继续使用原有扫描、安装补丁、安装回滚和任务详情页面，不新增 iframe，不复制第二套主机概览。

前端不直接调用 Relay、scan-api 或 `/desktop-agent/` 的业务接口；所有业务操作只调用 OpsMind 后端。

## 前置输入

后端需先提供：

- 主机列表新增字段契约。
- Agent 纳管与绑定接口。
- 扫描、安装、回滚的统一任务接口。
- 任务详情新增执行通道与 Relay 追踪字段。
- 权限点和错误码。

接口路径沿用 OpsMind 现有路由规范；以下字段名作为前后端固定契约。

## 任务 F1：主机概览支持双接入方式

在现有主机列表增加：

- `connectionType`: `ssh | koreops_agent`
- `agentStatus`: `online | offline | unknown`
- `agentVersion`
- `agentClientId`
- `capabilities`: `scan | patch | rollback | exec | put | fetch`
- `lastSeenAt`

展示要求：

- 增加“接入方式”列：显示“SSH”或“Agent”。
- Agent 主机显示在线状态和版本；SSH 主机不显示 Agent 状态。
- 一台主机只显示一行，不能因同时有 IP 和 client_id 产生重复资产。
- Agent 离线不等于主机被删除；显示“Agent 离线”并保留最后在线时间。
- 支持按接入方式和在线状态筛选。

## 任务 F2：操作按钮按能力控制

现有“扫描、安装补丁、安装回滚”按钮继续保留，但根据后端返回的 `capabilities` 和状态控制：

- Agent 在线且包含对应 capability：按钮可用。
- Agent 离线：按钮禁用，提示“Agent 离线，暂不可执行”。
- 不支持回滚：回滚按钮禁用，提示具体原因。
- SSH 主机保持现有行为。
- 混合批量选择时，前端展示可执行数量和不可执行原因；禁止静默跳过。

不要在前端根据版本号自行推断能力，能力判断以后端返回为准。

## 任务 F3：Agent 纳管入口

将“安装 Agent”放入现有“新增/纳管主机”流程，而不是新建业务控制台。

流程：

1. 用户选择“Agent 接入”。
2. 调用后端生成一次性 enrollment token。
3. 展示安装命令、有效期和剩余使用次数。
4. 进入“等待上线”状态并轮询 OpsMind 后端，不直接轮询 Relay。
5. 新 Agent 注册后，展示候选主机信息：hostname、IP、OS、client_id。
6. 用户确认绑定到已有资产或创建新资产。
7. 成功后跳转到原主机详情。

必须处理：

- token 过期、耗尽、撤销。
- 同一 Agent 重复注册。
- IP 命中多台已有资产。
- client_id 已绑定其他资产。

## 任务 F4：统一任务详情

扫描、安装和回滚仍进入 OpsMind 原任务详情页，新增只读字段：

- `executionChannel`: `ssh | agent`
- `agentClientId`
- `relayTraceId`
- `agentVersion`
- `dispatchStatus`

任务时间线至少显示：

- 排队
- 前置检查
- 已下发 Agent
- 执行中
- 结果回传
- 成功 / 失败 / 等待 Agent 重连

错误文案必须区分：

- Agent 离线
- Relay 不可达
- token 无效
- 任务超时
- 主机命令执行失败
- 结果回写失败

## 任务 F5：扫描结果与主机统计

前端只读取 OpsMind 原有漏洞/CVE接口：

- Agent 扫描完成后，主机行严重度统计和最后扫描时间自动刷新。
- 漏洞详情显示扫描来源 `SSH` 或 `Agent`，但不提供第二份 Relay 漏洞列表。
- 禁止把 `relay-demo`、包样例或 `KOREOPS-DEMO-*` 显示为正式生产漏洞。

## 任务 F6：安装与回滚

继续复用现有安装和回滚页面：

- Agent 主机创建任务时无需用户输入 SSH 凭据。
- 安装前展示后端返回的回滚能力与风险。
- 仅当任务返回 `rollbackSupported=true` 时允许创建回滚。
- 回滚结果进入原任务历史。
- 不增加“模拟回滚”按钮。

## 任务 F7：通道诊断入口

`/desktop-agent/` 改为管理员诊断入口，不作为普通补丁管理员主流程：

- 可从主机详情的“Agent 通道诊断”打开。
- 仅管理员可见。
- 页面展示注册、心跳、版本、能力和连接日志。
- 裸命令下发移入高级区并受独立权限控制。

## 权限点

前端需接入后端提供的权限码：

- 查看 Agent 状态
- 生成 enrollment token
- 绑定/解绑 Agent
- 发起扫描
- 发起补丁安装
- 发起回滚
- 查看 Relay 诊断
- 高级命令执行

不能只通过隐藏按钮实现授权。

## 前端验收

1. SSH 与 Agent 主机在同一主机概览展示，样式和筛选一致。
2. `desk-95-001` 只显示一条记录，接入方式为 Agent。
3. Agent 离线后主机仍存在，操作按钮和提示正确。
4. 从纳管流程生成命令并完成绑定后跳转原主机详情。
5. 从原按钮发起扫描，任务详情显示 Agent 通道和完整进度。
6. 扫描完成后原主机统计和漏洞列表更新。
7. 安装与回滚使用原页面、原任务历史。
8. 普通用户无法看到高级命令入口。

## 前端不负责

- 不直接访问 Relay/scan-api。
- 不在浏览器中拼装 Ansible inventory。
- 不判断补丁是否可回滚。
- 不把 Agent 注册表当作主机资产库。
- 不复制一套独立漏洞、安装或回滚页面。
