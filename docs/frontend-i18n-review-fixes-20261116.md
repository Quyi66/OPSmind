# 国际化审查修复与提交说明

本轮根据同事的审查意见修复搜索响应性和旧词库别名命名，并将此前留在工作区的 Linux/CVE、Windows/日志、巡检改造按主题提交。交付语言仍为简体中文和英文，繁体扩展机制保留；后端中文、用户脚本/文件及接口协议值不翻译。

## 搜索响应性修复

`useLazyDisplayList` 恢复使用 `computed` 计算过滤结果。关键词变化后同步读取即可得到新结果，搜索函数读取的响应式列表项属性变化也会重新匹配，不再只依赖数组引用及成员变化。

数组结构变化和关键词变化会重置可见条数，单个列表项属性变化只更新匹配。原有加载更多、空关键词和大小写/首尾空格处理保持。

切换语言时保留摘要搜索命中的需求由显式搜索上下文处理：

- 通用列表支持 `getSearchContext`，只在输入关键词变化时捕获上下文，作为 `searchFn` 的第三个参数；通用模块不依赖国际化服务。
- 安装/回滚摘要将搜索时的语言记录为上下文；本地摘要提供 `getSearchText(locale)`，按指定语言格式化搜索文本，可见文字继续使用当前语言。
- 不缓存整个命中数组，也不跳过某次 locale 变化对应的数据更新。语言和列表项同时变化时，数据仍按捕获的搜索语言重新匹配。
- 后端标题、主机名和普通原文继续作为原始文本搜索，不为它们猜测翻译。

新增六项通用列表回归覆盖同步查询、项属性进入/离开命中、默认字符串转换、数组增删/替换/排序、加载条数及语言上下文与数据同时变化；已有向导用例继续验证语言切换后的搜索命中和已加载页保持。

## 旧词库别名修复

`app_vap.menu.patch_scan.title` 现在指向语义化的 `patches.actions.scan`，对应扫描筛选、历史动作显示和本地结果标题也使用这个键。

`execution.tools.0g3GfW` 保留用于既有内置工具展示，实际扫描 `jobId: '0g3GfW'`、API 地址和执行参数保持。其余七个新增 `app_vap.*` 别名原已使用语义化键，沿用现有映射。补充测试验证中英文别名解析、固定简体查询和工具展示兼容。
