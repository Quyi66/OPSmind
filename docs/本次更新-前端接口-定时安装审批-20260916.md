# 前端接口变更：一键分批安装改为「定时 + 审批」

前缀：`/sjxy-console/secops/api/secops/v2/patch/task`

分支：`feature/patch-install-approval-schedule`（基于 `sjxy-init`）  
现场 SQL：`sjxy-dashboard/src/main/resources/db/migration/V17__patch_install_task_schedule_approval.sql`（Flyway 自动执行；手工部署直接跑该文件）

---

## 1. 业务规则

- 「包集安装 → 一键分批安装」不再立即执行。**软件包 + 目标主机 + 计划执行时间** 三项齐全才能提交，提交后生成一个定时任务。
- 普通用户提交的是**申请**（`status = PENDING_APPROVAL`），管理员（登录名 `admin`）审批通过后才会执行；管理员自己提交的不用审批，直接 `CREATED`。
- 到了计划执行时间由系统自动触发（预检查 → 通过即分批安装，默认不重启），流程和原来"立即开始"一样，后面的状态轮询不变。
- 到点仍未审批通过的申请自动变为 `EXPIRED`（失效）；已批准但超过计划时间 30 分钟仍未能触发（例如服务当时停了）的，也置 `EXPIRED`。
- 未到计划时间、待审批、已驳回、已失效的任务，调 `pre-check/execute` / `pre-check/skip` / `install/execute` 一律返回 400，页面上不要再对这类任务放"执行"按钮。

## 2. 创建：`POST /create-and-run`

URL / 方法 / 权限不变。**新增必填字段 `scheduledTime`**：

```json
{
  "packageSetId": "xxx",            // 或 packages
  "packages": ["openssl", "curl==7.61.1"],
  "targets": [ { "key": "<主机id>" } ],
  "batchSize": 50,
  "scheduledTime": "2026-09-20 02:00:00"   // 或毫秒时间戳；必须晚于当前时间
}
```

返回 task 实体（不再是已开始预检查的任务）：

| 字段 | 说明 |
| --- | --- |
| `status` | 普通用户 `PENDING_APPROVAL`；管理员 `CREATED` |
| `scheduledTime` | 计划执行时间 |
| `createdBy` | 申请人 |
| `approvedBy` / `approvedTime` / `approvalComment` | 审批信息，未审批为 `null` |

400 情形：`scheduledTime 不能为空`、`计划执行时间必须晚于当前时间`、`scheduledTime 格式错误…`，其余同原接口。

建议按钮文案由"立即开始一键分批更新"改为"提交定时安装"（管理员）/ "提交安装申请"（普通用户）。

## 3. 审批（仅管理员）：`POST /{id}/approval`

```json
{ "approved": true, "comment": "同意，注意窗口期" }
{ "approved": false, "comment": "包版本不对，请重提" }
```

- 通过 → `status = CREATED`，等待到点触发
- 驳回 → `status = REJECTED`，`errorMessage = "审批驳回：<comment>"`
- 非管理员调用 → 400 `只有管理员可以审批`
- 计划时间已过再点通过 → 任务直接置 `EXPIRED`，返回 400 `计划执行时间已过，任务已自动失效，请让申请人重新提交`

**待审批列表**：`GET /list?status=PENDING_APPROVAL`（管理员看到租户下全部；普通用户只看到自己的）。列表返回的就是 task 实体，包含 `packages`（装哪些包）、`hostIds`（哪些机器）、`scheduledTime`（什么时间）、`createdBy`（谁申请的）。

## 4. 状态取值新增

| status | 含义 | 终态 |
| --- | --- | --- |
| `PENDING_APPROVAL` | 待管理员审批 | 否 |
| `CREATED` | 已批准 / 管理员自建，等待到点触发（`scheduledTime` 非空时） | 否 |
| `REJECTED` | 审批驳回 | 是 |
| `EXPIRED` | 到点未批准 / 超时未触发，自动失效，原因在 `errorMessage` | 是 |

原有 `PRE_CHECKING → … → COMPLETED / *_FAILED` 不变。`GET /{id}/audit/detail` 的 `logs` 里会多出 `step=CREATE` 下的 `APPROVE` / `REJECT` / `EXPIRE` 记录。

## 5. 后端部署备注

- 定时触发器 `PatchInstallScheduleTrigger` 每 60 秒轮询一次（`sjxy.secops.install_schedule.poll_ms`），宽限期 `sjxy.secops.install_schedule.fire_grace_minutes` 默认 30。
- 触发时用 `workflow.run.apikey.<tenantId>` 给申请人换取令牌后调本机 `pre-check/execute`，与平台 XXL-JOB 定时任务同一机制；该配置缺失时任务不会执行，`errorMessage` 会写明 `未配置 workflow.run.apikey.<tenantId>`。
