## 历史页签

根据历史路由确认三个旧静态名称：`/acm/model` 的“模型定义”、巡检拓扑路由的“架构图”，以及旧分支 `/patches/urgencyDashboard` 的“紧急度评估”。英文展示分别使用 Asset types、Business topology、Urgency assessment。最后一项只翻译已有缓存页签，不注册路由、不恢复页面。

匹配限定为已知路径/路由 key 和准确的旧名称；任意自定义标题仍保留原文。中文显示和原缓存对象不变。单元测试覆盖准确匹配、其他路径不匹配、自定义标题、语言往返和缓存不变。

真实组件复核临时替换专用会话内存中的页签，检查中英文标签及自定义标题，再恢复原列表、路由和语言；没有改写认证资料或构造后台业务数据。这个历史缓存场景与正常菜单采集分开记录，不能当作实际打开了已移除的页面。

## 如何复查

从已登录账号的实际菜单发现 60 个页面，以中英文及 1440、1920 CSS 像素窗口采集，补充已审查只读标签页和横向隐藏列。后续修复使用定向采集覆盖相同页面/语言/宽度的旧结果，不重复累加为额外覆盖。

- [最近汇总的菜单采集索引](../.cache/i18n-first-page-reviewed-20261117/index.html)：240 个菜单首屏、315 个状态，早于资产类型最后增量；索引已添加暂停说明，不能据此把当前代码全部判为通过。
- [More 菜单与历史页签实际组件复核](../.cache/i18n-first-page-runtime/2026-11-17T03-35-55-868Z/report.json)：打开两处 More 检查菜单内容，没有点击执行、复制、删除或采集动作；历史页签使用上节说明的本地内存场景。
- 本轮人工查看了操作列调整前后的实际截图，重点核对单行按钮、列宽占比、数据区空间、表头/排序图标、日期，以及菜单展开效果。没有把全部采集截图自动等同为逐张人工验收。

工具增加完整单词/排序图标换行、按钮分行、操作列留白、AM/PM 日期分行、全部历史中文标签的复核候选。动作检查覆盖全部可见行，避免靠后记录带有额外报表按钮时漏检。规则只提供候选；有意的省略号和自定义标题仍需人工判读。

工具同时记录数据行数、空表、错误提示及同源请求失败。请求失败和错误提示会影响采集结果及退出码。调试阶段曾遇到查询失败空表，以及修改开发模块导致的页面上下文中断；这些旧报告保留，不计为有效验收结果。
