# 设备选择后直接执行

适用于只需要选择设备即可执行的功能，例如连通性检查、信息数据采集。
点击功能按钮直接打开 `AcmDeviceSelectorDialog`，最终执行按钮发起请求。
需要额外填写业务参数的表单继续使用 `AcmDeviceSelector`。

## 接入方式

```vue
<AcmDeviceSelectorDialog
  v-model="selectorVisible"
  ci-types="[auto]"
  :options="selectorOptions"
  title="选择设备 · 连通性检测"
  confirm-text="检查连通性"
  description="任务可能需要数分钟，点击“检查连通性”后立即执行。"
  :allow-empty="false"
  :close-on-confirm="false"
  :submitting="submitting"
  @confirm="submit"
/>
```

从 `@/modules/automation/components/job/schedule/components/AcmDeviceSelectorDialog.vue` 引入。

| 属性             | 默认值     | 用途                                             |
| ---------------- | ---------- | ------------------------------------------------ |
| `title`          | `选择设备` | 展示当前业务动作                                 |
| `confirmText`    | `确定`     | 使用明确的执行文案                               |
| `description`    | 空字符串   | 展示执行说明、耗时等提示                         |
| `allowEmpty`     | `true`     | 直接执行时设为 `false`，禁止空选择               |
| `closeOnConfirm` | `true`     | 直接执行时设为 `false`，由业务页面控制成功后关闭 |
| `submitting`     | `false`    | 请求中显示加载状态，禁止确认、取消和关闭         |

`confirm` 事件提供完整选择数组，包含跨 CI 类型的选择及分组、标签等选择项。
页脚数量按选择项统计，不能作为展开后的实际设备数量。
原有 `ciTypes`、`options`、`initialSelection` 用法保持不变。

## 业务页面职责

1. 功能按钮只打开选择器，不再套一层动作弹窗。
2. 在最终按钮和说明中明确点击后会立即执行，不再增加一次普通确认弹窗。
3. 提交函数先检查 `submitting`，同步设为 `true`，防止重复请求。
4. 使用 `normalizeAcmDeviceJobHosts` 转换选择，保留真实 ID、类型和选择模式。
5. 请求成功发起后关闭选择器，并展示原有执行结果；请求失败或返回业务失败时保留弹窗及选择供重试。
6. 在 `finally` 中恢复 `submitting`。选择器不会自动等待 `confirm` 事件处理函数。

重新打开时从 `initialSelection` 初始化；省略该属性时，每次打开都从空选择开始。
提交失败后不要关闭或重新挂载组件，这样可以保留选择状态。

已接入示例：`src/modules/asset/views/ExceptionDevicePage.vue`。

选择器支持 `context` 作用域插槽，其 `selection` 为当前全部选择，可用于展示待执行命令、仓库和目标摘要。设备数量展示统一使用 `DeviceSelectionSummary`，区分设备、分组和标签，不将选择项数量等同于设备总量。

当前菜单中的后续交互优化及验收清单见[当前菜单设备执行交互优化](./当前菜单设备执行交互优化-20261105.md)。下表记录之前的迁移历史，包含隐藏入口。

## 系统排查与迁移范围

| 模块         | 已改造入口                     | 保留的业务上下文                             |
| ------------ | ------------------------------ | -------------------------------------------- |
| 资产         | 连通性检查、信息数据采集       | 作业 ID、运行结果与历史日志                  |
| Linux 补丁   | 重新扫描、单台和批量主机扫描   | 工作台预选主机、原设备 ID、运行记录          |
| YUM 源       | 扫描主机 YUM 源                | `yum-list` 作业参数及完成后的刷新            |
| Windows 补丁 | 创建扫描任务                   | Windows 类型、预选主机及原轮询、列表刷新     |
| 软件仓库     | 设置基准仓库主机               | 原 hosts 参数                                |
| 软件仓库     | 自定义仓库、基准仓库配置到主机 | 已选仓库数量及原仓库 ID 参数                 |
| 软件概览     | 软件包重新扫描                 | 原扫描及完成后的刷新，现有隐藏入口不重新启用 |
| 主机用户     | 扫描主机用户                   | 采集说明、轮询、结果未知时禁止重复提交       |
| sudo 权限    | 扫描主机                       | 原轮询、扫描进度及完成后的列表刷新           |
| 命令管理     | 直接执行命令                   | 已选命令及原动态执行请求                     |

提交后需要持续反馈的扫描可以展示进度或结果窗口；不再在执行前套一层设备选择表单。
`submitting` 仅表示启动请求尚未返回，不能覆盖整个后台执行周期。Windows 扫描提交后关闭选择器并打开可关闭的结果窗口，完成观察独立于该结果窗口；YUM 和软件包扫描同样在请求返回后解除提交锁定。
主机用户扫描继续沿用原有结果未知处理：保留目标和原因，不因请求异常自动允许重复下发。

工作台的命令面板当前被 `showCommandWorkbenchPanel = false` 隐藏，软件概览的重新扫描按钮也被注释；两者不作为当前页面上的可点击入口，复用逻辑由定向测试覆盖。

下列使用位置包含额外参数或属于页面筛选，本次保留表单流程：

- 用户创建、修改、删除组等：需要用户名、组名、密码或具体操作参数。
- 临时密码申请、批量密码修改、sudo 申请与密码重置：需要用途、时长、用户或密码。
- 设备纳管和 Agent 注册：需要凭据、自动化配置或安装参数。
- 巡检模板编辑与执行、自动化流程和作业创建、定时作业参数：需要脚本、任务或其它执行参数。
- 命令控制台和创建命令运维工具：需要命令内容、标题等输入；仅直接执行模式改为选择后执行。
- 本地软件包安装、包集定时安装：需要软件包、执行时间或批次参数。
- Windows 补丁报告：还需选择严重级别及补丁状态，且空选择表示导出全部主机。
- 软件包清单、密码管理员面板等页面上的设备筛选：继续使用表单设备选择器。
