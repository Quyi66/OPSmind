# 前端接口变更（20261012）

前缀：`/sjxy-console/secops`

---

## 1. 运行记录：Windows 回滚有了独立的 action

运行记录（审计日志）的 `action` 字段：

| 操作 | 原来 | 现在 |
| --- | --- | --- |
| Linux 补丁安装 | `补丁安装` | `补丁安装`（不变） |
| Linux 补丁回滚 | `补丁回滚` | `补丁回滚`（不变） |
| Windows 补丁安装 | `Windows补丁安装` | `Windows补丁安装`（不变） |
| Windows 补丁回滚 | `补丁回滚`（与 Linux 相同，只能靠 `message` 区分） | `Windows补丁回滚` |

**前端要改：** 按 `action` 区分 Linux 和 Windows 回滚，不要再解析 `message`。凡是按 `action == '补丁回滚'` 做判断（显示图标、筛选、下载报告按钮等）的地方，都要同时处理 `Windows补丁回滚`。

更新前已经产生的 Windows 回滚记录仍是 `补丁回滚`，不会被改写。

---

## 2. Windows 补丁安装 / 回滚报告

后端现在会为 Windows 安装和回滚生成 Excel 报告，生成位置和取法与 Linux 完全一致。下载接口不变：

`GET /api/secops/v2/download/filename?runId={run_id}&dir={dir}`

| 运行记录 action | dir |
| --- | --- |
| `补丁安装` | `patch_install` |
| `补丁回滚` | `patch_rollback` |
| `Windows补丁安装` | `patch_install`（新增） |
| `Windows补丁回滚` | `patch_rollback`（新增） |

返回 `{"filePath": "2026-10-12 16:31:59_{runId}.xlsx"}`，`filePath` 为空字符串表示没有报告。拿到 `filePath` 后的下载方式与 Linux 报告相同。

**前端要改：** `Windows补丁安装`、`Windows补丁回滚` 两种运行记录也要显示「下载报告」按钮，`dir` 按上表传。

报告列：

| 主机 | 主机ID | 补丁编号 | 补丁名称 | 安装结果 / 回滚结果 | 失败原因 |
| --- | --- | --- | --- | --- | --- |
| 192.168.1.93 | CJBiP72SyYH0swgFfnA7 | KB5088864 | 2026-05 用于 .NET Framework ... | 安装失败 | 0x80240438 ... |

- 安装结果：`安装成功`、`安装成功（待重启生效）`、`安装失败`。
- 回滚结果：`回滚成功`、`回滚成功（待重启生效）`、`回滚失败`。
- 失败原因：目标机回传的报错；主机不可达、一条结果都没回传时为 `目标机未回传结果（主机不可达或作业执行失败），详见原始输出`。成功的行为空。

主机不可达导致整次作业失败时也会生成报告（所有补丁都是失败），所以失败的运行记录同样可以显示「下载报告」按钮。
