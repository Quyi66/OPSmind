# 资产导出 - 前端接口文档

分支：`boc-3.10.9`　日期：2026-11-16

## 1. 功能

在"设备清单"页把已录入的设备导出成 Excel，供用户和自己的设备台账核对，找出录入时的遗漏。

- 每个资产类型一个 sheet（`Linux服务器`、`Windows主机`……），格式与"导入设备"的模板一致。
- 除模板里的列以外，还带出平台里设置的信息：在线状态、网络区域、标签、所属分组、凭据模板、端口列表。
- 密码不导出。

## 2. 接口

```
POST {网关}/cmdb/api/cmdb/ci/export-assets
```

例：`http://<host>/sjxy-console/cmdb/api/cmdb/ci/export-assets`

请求头与其它 cmdb 接口相同（`Authorization`、`Tenant-Id`），`Content-Type: application/json`。

### 请求体

两个字段都可以不传；不传请求体等于导出全部。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `ciType` | string | 否 | 资产类型 code，如 `linux`、`windows`；多个用逗号分隔。不传 = 全部类型 |
| `ids` | string[] | 否 | 只导出这些设备（设备 id，即列表行的 `id`）。不传或空数组 = 导出 `ciType` 下当前用户有权限查看的全部设备。也接受逗号分隔的字符串 |

两个字段同时传时取交集：只导出 `ids` 中属于 `ciType` 的设备。

```jsonc
// 导出当前 tab（Linux服务器）的全部设备
{ "ciType": "linux" }

// 导出勾选的设备
{ "ciType": "linux", "ids": ["06veQrdcfYH3rWZaD5LK", "IMmtvf"] }

// 导出所有类型的全部设备
{}
```

### 成功响应

HTTP 200，响应体是 xlsx 文件的二进制内容。

| 响应头 | 值 |
| --- | --- |
| `Content-Type` | `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` |
| `Content-Disposition` | `attachment;filename*=utf-8''%E8%B5%84%E4%BA%A7%E5%AF%BC%E5%87%BA_20261116160830.xlsx`（解码后为 `资产导出_yyyyMMddHHmmss.xlsx`） |

### 失败响应

HTTP 400，响应体是 JSON：

```json
{ "error": "没有可导出的设备" }
```

| `error` | 出现的情况 |
| --- | --- |
| `资产类型不存在: xxx` | `ciType` 里有不存在的 code |
| `没有可导出的设备` | 该类型下没有设备、`ids` 都不存在，或当前用户对这些设备都没有查看权限 |

### 调用示例

请求要用 `responseType: 'blob'`。失败时响应体也是 Blob，需要先读成文本再取 `error`。

```js
async function exportAssets(ciType, ids) {
  try {
    const res = await axios.post('/cmdb/api/cmdb/ci/export-assets', { ciType, ids }, { responseType: 'blob' })
    const match = /filename\*=utf-8''(.+)$/i.exec(res.headers['content-disposition'] || '')
    const fileName = match ? decodeURIComponent(match[1]) : '资产导出.xlsx'
    const url = URL.createObjectURL(res.data)
    const a = document.createElement('a')
    a.href = url
    a.download = fileName
    a.click()
    URL.revokeObjectURL(url)
  } catch (e) {
    const blob = e.response && e.response.data
    const text = blob instanceof Blob ? await blob.text() : ''
    let message = '导出失败'
    try {
      message = JSON.parse(text).error || message
    } catch (ignore) {}
    this.$message.error(message)
  }
}
```

## 3. 页面入口建议

| 位置 | 按钮 | 请求体 |
| --- | --- | --- |
| 工具栏，"导入设备"旁边 | 导出设备 | `{ ciType: 当前 tab 的类型 code }` |
| "更多操作"菜单（已勾选设备时） | 导出所选设备 | `{ ciType: 当前 tab 的类型 code, ids: 勾选的设备 id }` |

- "全部筛选结果"（如截图里的"已选择 445 台设备"）和批量修改、批量删除一样，把筛选结果的 id 全部放进 `ids`。接口本身不接收筛选条件。
- 没有筛选、要导出整个 tab 时不要传 `ids`，只传 `ciType`。

## 4. 导出文件的内容

每个 sheet 第一行是表头（已冻结），一台设备一行，按纳管 IP 从小到大排列。列从左到右分三段：

| 段 | 列 | 表头颜色 | 说明 |
| --- | --- | --- | --- |
| ① 模板列 | 与"导入设备"模板该 sheet 的列完全相同，顺序相同 | 必填红、选填绿（同模板） | 资产类型里定义的属性，含自定义属性 |
| ② 内置列 | 运行环境、处置团队、应用系统、主机风险等级、SSH端口、业务端口、端口 | 绿 | 模板里没有、但导入时认的列。只有至少一台设备填了值，对应的列才出现 |
| ③ 平台设置 | 在线状态、网络区域、标签、所属分组、凭据模板、端口列表 | 灰 | 固定 6 列，总在最后 |

几个列的取值：

| 列 | 取值 |
| --- | --- |
| Ansible登录用户密码、Ansible执行用户密码 | 始终为空 |
| Ansible登录用户、Ansible执行用户、Ansible执行节点 | 设备当前生效的凭据设置 |
| path | 设备所在分组的路径，如 `/生产/22端口`。设备在多个分组时只写第一个，完整列表见"所属分组" |
| 在线状态 | `在线` / `下线` |
| 网络区域 | `互联网` / `外联网` / `内网环境、孤岛环境`，没设置为空 |
| 标签 | 设备上的标签，多个用 `;` 分隔 |
| 所属分组 | 设备所在的全部分组路径，多个用 `;` 分隔；只列最末一级，不重复列上级分组 |
| 凭据模板 | 设备关联的凭据模板名称 |
| 端口列表 | `名称:端口`，多个用 `;` 分隔，如 `SSH:22;HTTP:8080` |

如果资产类型里有自定义属性正好叫"标签"这类名字，③ 里的同名列会显示成 `标签（平台）`，避免两列同名。

## 5. 导出文件再导入

导出文件是给用户核对用的。因为 ①② 的列名和导入模板一致，文件也能被"导入设备"读进去，但**这条路径这次没有实测**，页面上不建议引导用户这么做。如果要导回，注意：

- ③ 的 6 列导入时不识别，会被忽略；在 Excel 里改这几列不会生效。
- 留空的单元格，导入后会把该设备对应的属性清空（导入功能原有的行为）。
- 密码列是空的。按导入代码的写法，空密码不会覆盖设备已保存的密码，但没有实际验证过，导回前先拿一台设备试。
